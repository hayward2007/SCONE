> 현재 가중치, 실제 35.4M-step 학습, 행동 포화와 actuator randomization 진단은
> [`21-walk-v2-ppo-training-analysis.md`](21-walk-v2-ppo-training-analysis.md)를

## 1. 액추에이터 모델

### 1.1 e-Manual 실사양 (12 V)

| 모델 | 스톨 토크 | 스톨 전류 | 무부하 속도 | 감속비 | 백래시 | 모터 |
| --- | ---: | ---: | ---: | ---: | ---: | --- |
| MX-28AT | 2.5 N·m | 1.4 A | 55 rev/min | 193 : 1 | 20′ (0.33°) | Coreless (Maxon) |
| XM430-W350-T | 4.1 N·m | 2.3 A | 46 rev/min | 353.5 : 1 | 15′ (0.25°) | Coreless |
| XM430-W210-T | 3.0 N·m | 2.3 A | 77 rev/min | 212.6 : 1 | 15′ (0.25°) | Coreless |

`model.xml`의 `<dcmotor nominal="전압 스톨토크 무부하속도">` 값은 **세 모델 모두
데이터시트와 일치**한다. 즉 입력 삼중항 자체는 옳다.

### 1.2 그런데 파생 상수가 데이터시트와 어긋난다

MuJoCo의 `nominal` 축약은 $K=V/\dot q_{\rm nl}$, $R=KV/\tau_{\rm stall}$로
전개된다. 이 관계로 스톨 전류를 되계산하면:

| 모델 | K [N·m/A] | R [Ω] | 모델 스톨 전류 | 실사양 | 오차 | 함의 효율 |
| --- | ---: | ---: | ---: | ---: | ---: | ---: |
| MX-28AT | 2.0835 | 10.00 | 1.200 A | 1.4 A | **−14 %** | 0.857 |
| XM430-W350-T | 2.4911 | 7.291 | 1.646 A | 2.3 A | **−28 %** | 0.716 |
| XM430-W210-T | 1.4882 | 5.953 | 2.016 A | 2.3 A | **−12 %** | 0.876 |

세 값(스톨 토크·무부하 속도·스톨 전류)을 이상적 DC 모터 하나로 동시에 만족시킬 수
없다. 차이는 **감속기 손실**이다. 마지막 열이 그 손실을 흡수한 등가 효율이며
0.72–0.88이다. 결과적으로:

- 시뮬레이션의 전기 에너지 추정 $E_e$는 실제보다 **12–28 % 낮게** 나온다.
- `stair_geometry.quasi_static_pivot_torque`의 기본 `efficiency=1.0`은 낙관적이다.
  **0.75–0.85를 쓰는 편이 실제에 가깝다.**

### 1.3 가장 큰 누락: 반사 관성(armature)

기존 `model.xml`의 18개 관절에는 `armature`, `damping`, `frictionloss`가 **전혀
없었다.** 감속비가 193–353:1인 서보에서 이것은 치명적이다. 반사 로터 관성은
$J_{\rm arm}=J_{\rm rotor}N^2$이고, SPORT 자세에서 실제 관절공간 관성과 비교하면:

| 관절 | 실제 $M_{ii}$ [kg m²] | N | $J_{\rm arm}$ ($J_{\rm rotor}=1.4\times10^{-7}$) | 비율 |
| --- | ---: | ---: | ---: | ---: |
| ID 1–6 (MX-28AT) | 0.02373 | 193.0 | 0.00521 | 0.22× |
| ID 7–12 (W350) | 0.01652 | 353.5 | 0.01749 | **1.06×** |
| ID 13–18 (W210) | 0.00253 | 212.6 | 0.00633 | **2.50×** |

즉 말단 관절에서 반사 관성이 링크 관성의 2.5배다. 이것을 빼놓으면 **말단 관절이
실제보다 한 자릿수 가깝게 민첩해진다.** sim-to-real 격차의 1순위 원인이다.

### 1.4 적용한 변경 (2026-09-02 재검토 후 수정)

**armature만 추가하고 damping/frictionloss는 넣지 않는다.**

| 관절군 | armature | damping | frictionloss |
| --- | ---: | ---: | ---: |
| ID 1–6 (MX-28AT) | 0.00521 | 0 | 0 |
| ID 7–12 (W350) | 0.01749 | 0 | 0 |
| ID 13–18 (W210) | 0.00633 | 0 | 0 |

처음에는 damping과 frictionloss도 함께 넣었는데, **이는 감속기 손실을 이중으로
계산한 오류였다.** e-Manual의 스톨 토크와 무부하 속도는 조립된 액추에이터의
**출력축에서 측정한 값**이므로 감속기·모터 손실이 이미 `nominal` 삼중항 안에 들어
있다. 모델은 정격 무부하 속도에서 정확히 순토크 0이 된다. 그 위에 마찰을 더하면
데이터시트보다 느려진다. 실측으로 확인했다.

| | 무부하 속도 (rad/s) | | | 스톨 토크 (N·m) | |
| --- | ---: | ---: | ---: | ---: | ---: |
| | 사양 | 마찰 추가 시 | 수정본 | 사양 | 모델 |
| MX-28AT | 5.760 | 5.545 (**−3.7 %**) | **5.760** | 2.5 | 2.5 |
| XM430-W350-T | 4.817 | 4.651 (**−3.4 %**) | **4.817** | 4.1 | 4.1 |
| XM430-W210-T | 8.063 | 7.821 (**−3.0 %**) | **8.063** | 3.0 | 3.0 |

마찰을 제거하니 두 데이터시트 끝점이 **오차 0.0 %로 재현**된다.

반면 **armature는 `nominal`에 들어 있지 않다.** 토크-속도 쌍은 정상상태 특성이라
반사 로터 관성에 대해 아무 말도 하지 않기 때문이다. 그래서 이것만 남긴다.

교차 검증: 이 값들이 주는 기계 시상수 $\tau_m = JR/K^2$는 12 ms, 21 ms, 17 ms로
같은 크기의 코어리스 모터에 맞는 범위다. 즉 $J_{\rm rotor}=1.4\times10^{-7}$
추정은 대략 2배 이내로 맞다. **정확히 고정하려면 무부하 스텝 응답에서 $\tau_m$을
맞추면 되고, 이 방법은 $J_{\rm rotor}$를 몰라도 된다.**

이 선택으로 생기는 알려진 한계: Coulomb 항이 없으므로 **토크를 끈 관절이 무마찰**
이다. 193–353:1 감속기의 역구동 저항이 모델에 없다. 충격과 무전원 지지에는
영향이 있고, 벤치마크가 측정하는 구동 상태 거동에는 영향이 적다. 나중에 마찰
분해를 실측하면 **같은 편집에서 `nominal`의 무부하 속도를 모터측 값으로 올려야
한다.** 그러지 않으면 실물보다 느린 액추에이터가 된다.

### 1.5 PD 이득 재조정 (armature가 깨뜨린 것)

`pid.py`의 주석은 "kd는 이 모델의 단별 유효 관성에 대한 임계감쇠"라고 명시한다.
기존 kd에서 역산한 관성이 내가 측정한 링크 관성과 거의 정확히 일치했다.

| 관절군 | kd로 역산한 $J_{\rm link}$ | 측정 $M_{ii}$ | 일치 |
| --- | ---: | ---: | --- |
| MX-28AT | 0.02467 | 0.02373 | ○ |
| W350 | 0.01668 | 0.01652 | ○ |
| W210 | 0.00253 | 0.00253 | ◎ |

armature를 더하면 유효 관성이 각각 **21 %, 105 %, 250 %** 늘어난다. 같은 kd로는
더 이상 임계감쇠가 아니다. 20° 스텝 응답 실측:

| 관절군 | armature 전 | armature 후 (kd 그대로) | kd 수정 후 |
| --- | ---: | ---: | ---: |
| ID 1–6 | 0.0 % 오버슈트 | 0.0 % | 0.0 % |
| ID 7–12 | 0.0 % | **4.6 %** | 0.0 % |
| ID 13–18 | 0.0 % | **13.6 %** | 0.0 % |

$k_d = 2\sqrt{k_p(J_{\rm link}+J_{\rm arm})}$로 다시 계산했다.

| 관절군 | kp | kd (이전 → 수정) |
| --- | ---: | ---: |
| mx28at | 5.73 | 0.752 → **0.828** |
| xm430_w350 | 9.40 | 0.792 → **1.134** |
| xm430_w210 | 6.88 | 0.264 → **0.494** |

> ⚠️ 이 변경은 기존 PPO 체크포인트가 학습한 액추에이터 동역학을 바꾼다.
> `pid.py`의 원래 주석이 우려하던 바로 그 지점이다. 다만 13.6 % 오버슈트를 두는
> 것보다는 낫고, walk_v2는 어차피 새로 학습한다.

tripod-gait, vx=0.30, 6 s. "오류본"은 마찰을 잘못 넣었던 중간 버전이다.

standard 자세에서 속도 −5.3 %, CoT +5.1 %. 잘못 넣었던 마찰 버전의 +38 %와 달리
반사 관성만의 정직한 대가다. **자세 순서(240/255 최적)는 바뀌지 않는다.**

> ⚠️ 그래도 `benchmark/results/*.jsonl`은 전부 무효다. 재실행 필요.

### 1.7 아직 남은 격차

- **연속 토크 한계.** `saturation`이 스톨 토크다. 실제로는 스톨을 연속 유지하면
  수 초 내 과열 보호가 걸린다. 열 모델이 없으므로 순시 한계는 그대로 두고, 새 PPO
  보상의 토크 비용 항으로 다룬다.
- **역구동 저항 없음** (§1.4의 알려진 한계).
- **백래시** 0.25–0.33°. 말단 호 반지름 0.1225 m에서 0.25°는 접촉점 0.53 mm.
- **통신 지연.** 새 환경에 1 스텝 행동 지연을 확률적으로 넣어 근사했다.
- **관절 가동 범위.** `model.xml`에 기계적 한계가 없다. 실측 필요.
- **전압 강하·온도 감쇠.** 미모델링.

## 2. 좌표계 규약과 이동 방향

### 2.1 문제

내보낸 섀시 프레임(`UPPER_BODY_1`)의 축이 로봇의 전방/좌측과 맞지 않는다. 두 가지
독립적인 근거가 같은 결론을 가리킨다.

1. **탑재물 배치.** `model.xml`은 내부 탑재물이 "front-to-rear" 순서라고 명시하고
   `BATTERY_L2_L1`(x=−0.005) → `RASPBERRY_PI` → `BATTERY_L4_L3` →
   `BATTERY_L6_L5`(x=+0.255)로 배치한다. 따라서 **1·2번 다리가 앞이고 전방은 −x**다.
2. **손잡이(handedness).** x가 전방, z가 위인 오른손 좌표계에서 +y는 반드시
   좌측이다. 그런데 오른쪽으로 명명·채색된 1·3·5번 다리가 +y에 있다. 즉
   섀시 프레임의 +y는 우측이다.

두 근거 모두 **섀시 프레임 = 정규 프레임을 z축으로 180° 회전한 것**을 뜻한다.

### 2.2 실측: 세 기준 모션의 이동 방향

기준 모션을 무잔차(zero residual)로 6 s 구동하고 몸체 좌표계 변위를 측정했다.

| 기준 모션 | vx=+0.30 | vx=−0.30 |
| --- | --- | --- |
| tripod-gait | dx=+0.109 | dx=−0.108 |
| scone-gait | dx=+0.005 | dx=−0.004 |
| hardcoded | dx=+0.453 | dx=−0.454 |

**부호는 셋 다 일치한다.** 하드코딩 기준의 `-command[0]`은 버그가 아니라 이미
적용된 보정이었다. 다만 크기가 전혀 달랐다: 하드코딩이 tripod-gait보다 4배 빠르고,
tripod-gait은 lateral이 되지만 하드코딩은 **vy를 아예 무시**하며, 회전은
하드코딩이 32배 빨랐다. **두 기준은 어느 축에서도 교환 가능하지 않다.**

여기에 `train` 기본값이 `tripod-gait`, `enjoy` 기본값이 `hardcoded`였으므로,
학습한 residual이 학습한 적 없는 기준 위에 얹혀 재생되고 있었다.

### 2.3 tripod gait의 yaw 회전 중심 버그

`TripodGait._stride_for_leg`는 $\omega\times r$의 $r$을 **섀시 프레임 원점 기준**
발 위치로 계산했다. 원점은 지지 다각형 중심에서 평면상 0.157 m 떨어져 있다.
따라서 순수 yaw 명령이 "회전 + 병진"으로 변질됐다.

측정 (yaw=+0.5 명령, 6 s):

| 회전 중심 | dyaw | dx | dy |
| --- | ---: | ---: | ---: |
| 섀시 원점 (기존) | +4.74° | +0.013 | **+0.039** |
| 발자국 중심 (수정) | +3.73° | −0.001 | **−0.008** |

병진 드리프트가 사라진다. `GaitConfig.yaw_about_footprint_centroid`(기본 True)로
수정했다.

### 2.4 적용

기존 코드 경로를 깨뜨리지 않기 위해 **모델은 회전시키지 않았다.** 대신 새 환경이
단일 상수로 변환한다.

```python
# src/rl/walk_v2.py
CANONICAL_FROM_CHASSIS = np.diag([-1.0, -1.0, 1.0])
```

관측·명령·보상은 전부 정규 프레임(x 전방, y 좌측, z 위)이고, 기준 gait에 명령을
넘길 때만 섀시 프레임으로 되돌린다. 의도한 전방이 반대라면 이 상수를 단위행렬로
바꾸면 된다.

### 2.5 수정 후 실측 (새 환경, 무잔차)

| 기준 | vx=+0.35 | vx=−0.35 | yaw=+0.9 |
| --- | ---: | ---: | ---: |
| tripod-gait | +0.107 | −0.124 | +0.334 rad/s |
| hardcoded | +0.096 | −0.109 | +0.435 rad/s |

세 축 모두 부호가 일치하고 크기도 같은 자릿수가 되었다. **yaw는 0.0138 → 0.334
rad/s로 24배 개선**됐다 (회전 중심 수정 + 보폭·주파수 상향).

### 2.6 남은 좌우 비대칭

직진 명령에서 4개 seed의 yaw 드리프트(미러링·랜덤화 끔):

| 기준 | 평균 yaw 드리프트 | seed별 |
| --- | ---: | --- |
| hardcoded | **−0.0001 rad/s** | −0.006, +0.006, −0.006, +0.006 |
| tripod-gait | **+0.0325 rad/s** | +0.009, +0.097, +0.031, −0.007 |

하드코딩 기준은 대칭이다(부호가 위상에 따라 교대). **tripod-gait은 평균이 양수로
치우쳐 있다** — 두 삼각보가 등가가 아니다. 기구는 대칭이 검증되었으므로 원인은 IK
분기 선택이나 stagger 쪽이다. 후속 조사 대상이며, 새 환경의 미러 증강이 정책
수준에서는 이를 상쇄한다.

## 3. 모터 번호와 색상 — 검증 결과 이상 없음

### 3.1 번호

몸체 좌표계 힙 위치:

| 다리 | 전후 (정규 x) | 좌우 (정규 y) | 측 |
| --- | ---: | ---: | --- |
| 1 | +0.005 (앞) | −0.000 | 우 |
| 2 | +0.005 (앞) | +0.191 | 좌 |
| 3 | −0.125 | −0.000 | 우 |
| 4 | −0.125 | +0.191 | 좌 |
| 5 | −0.255 (뒤) | −0.000 | 우 |
| 6 | −0.255 (뒤) | +0.191 | 좌 |

정규 프레임에서 **1·3·5가 우측(−y), 2·4·6이 좌측(+y)**이고 1·2가 앞, 5·6이 뒤다.
요구한 규약과 일치한다.

### 3.2 기구 좌우 대칭 — 검증됨

몸체 $xz$ 평면 기준 축벡터 거울상 판정에서 **9개 관절 쌍 전부 통과**했다.
SPORT 자세 실제 접촉 중심의 좌우 오차는 x 1.1 mm, y 1.2 mm, z 3.4 mm로 CAD 반올림
수준이다. `degrees_to_raw`가 모터 ID를 무시하므로 **좌우에 같은 각도를 주면 정확히
거울 자세가 나온다.** 미러 사상은 부호 없는 단순 치환이다.

## 4. 몸체 높이 — 낮은 게 유리한가 높은 게 유리한가

중간/말단 관절 각도를 바꿔 다섯 자세를 실측했다 (vx=0.30, 6 s).

### 하드코딩 기준 (관절각 고정 20° 스윙)

| 중간/말단 | 높이 | 속도 [m/s] | CoT | z rms |
| --- | ---: | ---: | ---: | ---: |
| 170/195 | 294 mm | 0.0755 | 1.010 | 4.11 mm |
| 190/210 | 362 mm | 0.0797 | 0.933 | 3.54 mm |
| **210/230** | **426 mm** | **0.0815** | **0.842** | 2.94 mm |
| 240/255 | 497 mm | 0.0539 | 0.866 | 1.21 mm |
| 260/270 | 520 mm | 0.0165 | 2.158 | 0.42 mm |

### tripod-gait 기준 (Cartesian 보폭 0.090 m 고정)

| 중간/말단 | 높이 | 속도 [m/s] | CoT |
| --- | ---: | ---: | ---: |
| 170/195 | 294 mm | 0.0365 | 1.922 |
| 190/210 | 362 mm | 0.0437 | 1.650 |
| 210/230 | 426 mm | 0.0637 | 1.220 |
| **240/255** | **497 mm** | **0.1173** | **0.662** |
| 260/270 | 520 mm | 0.0765 | 1.015 |

### 결론

**standard가 사용 가능한 프리셋 중 가장 높고, 측정상으로도 가장 좋다.**
`STANCE_PRESETS`에 있는 자세는 `sport`(294 mm)와 `standard`(497 mm) 둘뿐이며
위 표의 190/210, 210/230, 260/270은 비교를 위해 임의로 만든 각도다. 즉 실제
선택지 안에서는 **더 높은 자세가 없고, standard를 쓰면 된다.**

그렇다고 "높을수록 좋다"는 아니다. 프리셋 밖인 260/270(520 mm)에서 두 기준 모두
급격히 나빠진다.

- **너무 낮으면**(294 mm) 다리가 접혀 있어 같은 관절 스윕이 만드는 수평 발
  변위가 작다. tripod-gait 기준으로 최적 대비 속도 1/3, CoT 2.9배.
- **standard보다 더 높이면**(520 mm) 다리가 신전 한계에 가까워 자코비안이
  특이해진다. 관절이 움직여도 발이 주로 수직으로만 움직이고, 지지 모멘트 팔이
  길어져 토크 경제가 나빠진다. standard가 그 붕괴 직전의 좋은 지점이다.
- 두 기준의 최적점이 426 mm와 497 mm로 다른 이유는 보폭 정의가 다르기 때문이다.
  관절각 고정 보폭은 낮은 자세를, Cartesian 보폭은 높은 자세를 선호한다.
  **두 결과가 겹치는 430–500 mm 구간이 안전한 선택**이다.

정리하면 **standard(497 mm)를 기본으로 쓰고, 그보다 더 펴지는 방향으로는 가지
않는다.** 새 환경의 높이 보상은 고정 목표값 대신 **해당 스탠스가 안정화된 높이를
목표로 삼도록**(`RewardConfig.target_height = None`) 해서, 어떤 프리셋을 골라도
보상이 자세와 싸우지 않는다.

> 여기서 곧바로 따라오는 문제: 기존 RL 환경의 기본 스탠스는 SPORT(294 mm)로
> **측정된 자세 중 가장 나쁜 것**이었다. 반면 벤치마크는 STANDARD(497 mm)를 쓴다
> (`articulated-walk` 실측 0.1171 m/s가 240/255 행의 0.1173과 일치한다).
> 학습과 평가가 서로 다른, 그것도 최악과 최적의 자세에서 이루어지고 있었다.
> 새 환경의 기본값은 `standard`로 바꿨다.

## 5. 보행 PPO 재설계 — `src/rl/walk_v2.py`

`walk_learn.py`는 기존 체크포인트 재생을 위해 그대로 두고 새 모듈을 추가했다.

### 5.1 이전 설계의 문제와 대응

| 문제 | 이전 | 새 설계 |
| --- | --- | --- |
| 기준 궤적이 명령보다 6배 느림 (도달 상한 0.084 m/s vs 명령 0.50) | f=0.7 Hz, 보폭 0.060 | f=1.2 Hz, 보폭 0.110, duty 0.5 → 상한 0.264 m/s, 명령 상한 0.35 |
| 속도 보상이 고속에서 소멸 | 지수항만 | 지수항 + **포화하지 않는 선형 progress 항** |
| 좌우 대칭 강제 장치 없음 | 없음 | **에피소드 단위 랜덤 미러**(p=0.5), 검증된 치환 사상 |
| 접촉 정보 없음 | 70차원 관측에 접촉 없음 | **접촉 플래그 6 + 정규화 수직력 6** 추가 (82차원) |
| 놀고 있는 다리에 벌점 없음 | 없음 | **air-time 보상 + 무접촉 시간 벌점 + 부하 분담 벌점** |
| 행동 크기 벌점이 다리를 끄도록 유도 | 0.25 균등 | **0.05**로 하향, 대신 토크 항 추가 |
| 헤딩 보상이 34° 폭으로 헐렁 | σ=0.60 rad | **σ=0.20 rad** |
| 착지 충격 무시 | 없음 | **수직력 상승률 벌점** (요청 항목) |
| 랜덤화 전무 | 위상만 | 관절 초기 노이즈, 초기 yaw, 질량·마찰·구동력 스케일, 외란 push, 관측 노이즈, 1스텝 행동 지연 |
| 자세가 최악 | SPORT 294 mm | **STANDARD 497 mm**, 목표 높이 0.46 m 보상 |
| 유효 지평이 보행 주기 1.4배 | γ=0.99, 10 s | γ=0.995, 20 s |
| 표본 부족 | 4 env × 1e6 | 64 env × 5e7 기본값 |

### 5.2 정규 프레임과 미러 사상

관측 82차원 배치와 미러 연산자:

| 구간 | 내용 | 미러 |
| --- | --- | --- |
| 0:3 | 선속도 (극벡터) | (+, −, +) |
| 3:6 | 각속도 (축벡터) | (−, +, −) |
| 6:9 | 투영 중력 | (+, −, +) |
| 9:27 | 관절 위치 | 치환 P |
| 27:45 | 관절 속도 | 치환 P |
| 45:63 | 이전 행동 | 치환 P |
| 63:66 | 명령 (vx, vy, ωz) | (+, −, −) |
| 66:68 | 위상 sin/cos | (−, −) — 미러가 삼각보를 맞바꾸므로 반주기 이동 |
| 68:70 | 헤딩 오차 sin/cos | (−, +) |
| 70:76 | 접촉 플래그 | 발 치환 |
| 76:82 | 정규화 수직력 | 발 치환 |

행동 18차원은 치환 P. `mirror_observation`, `mirror_action`은 대합(involutive)임을
단위 검사로 확인했다.

### 5.3 보상 항

| 항 | 가중치 | 목적 |
| --- | ---: | --- |
| velocity (지수, σ=0.20) | 2.0 | 명령 추종 |
| **progress (선형, 비포화)** | 1.5 | 고속 구간에서도 gradient 유지 |
| yaw (지수, σ=0.25) | 0.8 | 회전 추종 |
| heading (지수, σ=0.20) | 1.0 | 직진 유지 |
| upright | 0.6 | 자세 |
| **air_time** | 0.6 | 착지 순간에만, 스윙 시간 0.25 s 목표 |
| height (목표 0.46 m 양방향) | 0.4 | 측정된 최적 자세 유지 |
| oscillation | 0.10 | 상하·롤·피치 진동 |
| **inactivity** | 1.0 | 1 s 이상 접촉 없는 다리에 벌점 |
| **load_share** | 0.3 | 여섯 발 수직력 분포 균등도 |
| **impact** | 0.5 | 수직력 상승률² — 부드러운 착지 |
| slip | 0.15 | 접촉 미끄럼 |
| joint_limit / torque / action_rate / action_magnitude / collision | 0.3 / 0.02 / 0.05 / 0.05 / 1.0 | 안전과 효율 |

`inactivity`와 `air_time`은 명령 활성도로 스케일되므로 정지 명령에서는 다리를
들라고 강요하지 않는다.

### 5.4 CLI

요청대로 기준 모션을 선택할 수 있다.

```bash
python -m src.rl.walk_v2 --reference-motion tripod-gait --curriculum easy check
python -m src.rl.walk_v2 --reference-motion hardcoded  --curriculum full  check --random-actions
python -m src.rl.walk_v2 --reference-motion none       train --num-envs 64 --timesteps 50000000
python -m src.rl.walk_v2 --reference-motion tripod-gait enjoy runs/walk_v2/final_model.zip
```

`none`은 기준 모션 없이 end-to-end로 학습한다. residual로 시작할 것을 권장하며,
`tripod-gait`은 lateral과 yaw를 제대로 만들고 `hardcoded`는 더 빠르지만 lateral이
없다. **먼저 `tripod-gait`으로 안정화한 뒤 `none`으로 옮기는 순서**가 안전하다.

### 5.5 스모크 테스트 결과

```
observation (82,)  action (18,)
tripod-gait, 무잔차, vx=0.35 명령 -> 실측 vx = +0.107 m/s
hardcoded,   무잔차, vx=0.35 명령 -> 실측 vx = +0.096 m/s
yaw=0.9 명령 -> tripod +0.334 rad/s, hardcoded +0.435 rad/s
```

위 표는 당시 정책 없이 기준 모션만 측정한 최초 스모크 결과다. 이후 실제 V2 학습을
35.4M step 이상 실행했으며, 최신 정책은 nominal 고정 명령 평가에서 zero residual을
이기지 못했다. 현재 결과와 원인은
[`21-walk-v2-ppo-training-analysis.md`](21-walk-v2-ppo-training-analysis.md)에 기록했다.

## 7. SSH 학습 (walk_v2)

`walk_v2`의 CLI 인자 배치를 `walk_learn`과 **동일하게** 맞췄기 때문에, 기존 SSH
런처(`src.rl.inquiry`)가 코드 변경 없이 v2를 그대로 구동한다.

### 7.1 런처에 등록

```python
# src/rl/inquiry.py
"walk-v2": TrainingTask(
    key="walk-v2",
    label="걷기 정책 v2 (정규 좌표계 · 좌우 대칭 · 접촉 보상)",
    module="src.rl.walk_v2",
    checkpoint_prefix="scone_walk_v2",
    reference_motions=("tripod-gait", "scone-gait", "hardcoded", "none"),
),
```

`TrainingTask`에 `reference_motions` 허용 목록을 추가했다. `walk_learn`에는
end-to-end 모드가 없으므로 `none`은 v2에서만 선택지로 뜨고, 잘못 짝지으면
`TrainingConfig`가 거부한다.

```
$ python -m src.rl
  무엇을 학습할까요?
  > 걷기 정책 (PPO residual walk)
    걷기 정책 v2 (정규 좌표계 · 좌우 대칭 · 접촉 보상)     <- 추가됨
```

이후 기존 흐름(원격 용량 조회 → 소스 동기화 → 의존성 확인 → detached 실행 →
로그/체크포인트 미러링 → 일시정지/재개)이 그대로 적용된다.

### 7.2 원격 실행 계약

런처가 만드는 detached 명령은 v2에서도 동일하게 동작한다.

| 경로 | 용도 |
| --- | --- |
| `runs/<name>/train.log` | `nohup` 출력 |
| `runs/<name>/train.pid` | 일시정지에 쓰는 PID |
| `runs/<name>/train.state` | `running` / `paused` |
| `runs/<name>/checkpoints/scone_walk_v2_<steps>_steps.zip` | 롤링 체크포인트 |
| `runs/<name>/resume.checkpoint` | 재개할 정확한 파일(run 디렉터리 상대경로) |
| `runs/<name>/final_model.zip` | 정상 종료 시 |

- `SIGTERM`(런처의 "일시정지")을 받으면 현재 rollout을 마치고 재개용 체크포인트를
  쓴 뒤 0으로 종료한다.
- 체크포인트 주기는 `--checkpoint-every / --num-envs` 스텝마다이고, 최신
  `--keep-checkpoints` 개만 남긴다.
- 모든 보상 항이 TensorBoard의 `reward/<항목>`으로 기록되므로 가중치 조정이
  눈으로 보인다.

검증한 내용(스텁 SB3로 실행):

```
save_freq = 25          (checkpoint_every 100 / num_envs 4)
prefix    = scone_walk_v2
kept      = [..._300_steps.zip, ..._400_steps.zip, ..._500_steps.zip]   keep_last=3
pointer   = checkpoints/scone_walk_v2_500_steps.zip
graceful  = True -> False (SIGTERM 이후)
tb        = {'reward/velocity': 2.0, 'reward/impact': -1.0}
```

그리고 런처가 생성한 인자 벡터를 `walk_v2`의 파서가 그대로 받는 것을 확인했다.

### 7.3 런처 없이 직접 SSH로

```bash
# 원격에서
cd ~/Developer/SCONE
mkdir -p runs/v2_easy/checkpoints
nohup env PYTHONPATH=. PYTHONUNBUFFERED=1 .venv/bin/python -m src.rl.walk_v2 \
    --terrain flat --terrain-seed 7 \
    --reference-motion tripod-gait --stance standard \
    train --curriculum easy --timesteps 50000000 --num-envs 16 \
    --checkpoint-every 500000 --keep-checkpoints 10 \
    --output runs/v2_easy --tensorboard-log runs/v2_easy/tensorboard \
    > runs/v2_easy/train.log 2>&1 < /dev/null &
echo $! > runs/v2_easy/train.pid

# 일시정지
kill -TERM "$(cat runs/v2_easy/train.pid)"

# 재개
... train ... --resume "runs/v2_easy/$(sed -n 1p runs/v2_easy/resume.checkpoint)" ...
```

`--num-envs`는 원격 코어 수에 맞춘다. 런처의 용량 조회가 권장치를 알려준다.

### 7.4 후속 완료 및 현재 남은 것

- `src/rl/remote_watch.py`와 로컬 replay 경로는 checkpoint 관측 shape를 판별해
  70차원 구형 환경과 82차원 V2 환경을 선택한다. V2 `step()`/외부 제어 경로의
  viewer sync도 복구했고 실제 `mjpython` 창을 확인했다(commit `4e449e2`).
- 원격 V2 학습은 실제로 35.4M step 이상 실행했다. 현재 남은 핵심은 실행 가능성이나
  viewer가 아니라, bounded action distribution, 누적되지 않는 actuator
  randomization, 안정적인 PPO update와 best-model 평가다. 상세 근거는
  [`21-walk-v2-ppo-training-analysis.md`](21-walk-v2-ppo-training-analysis.md)를 따른다.
