# `walk_v3` 설계와 보정 (2026-09-02)

`walk_v2`는 재설계한 보상·관측·PPO 설정을 모두 적용한 뒤에도 **zero residual 기준
모션을 이기지 못했다**(docs/21 §11.0). 그래서 v3는 v2 계열을 더 손보는 대신,
실제로 동작했던 `walk_learn`(v1)의 **하드코딩 삼각보 + residual RL** 구조로 돌아가
그 구조의 상한 세 가지를 제거한다.

`walk_learn.py`와 `walk_v2.py`는 건드리지 않았으므로 기존 체크포인트는 그대로
재생된다.

---

## 1. 요구사항과 구현 대응

| 요구사항 | v1의 상태 | v3 구현 |
| --- | --- | --- |
| 속도 상한 없음 | 명령 범위 0.30~0.50 m/s인데 기준 모션은 0.10 m/s에서 포화 → 고속 구간에 gradient 없음 (docs/17 §2) | 기준 모션의 stride·lift·cadence를 **명령에서 역산**(측정 보정표), 명령은 clip하지 않음, 속도 보상은 **단측(one-sided)** — 명령 초과에 벌점 없음 |
| 몸체 높이는 움직여도 됨 | `height_weight` 벌점 + `max_height_drop` 종료 + 수직속도 진동 벌점 | 높이 항 **없음**, 높이 종료 **없음**, 수직속도 벌점 **없음**. 붕괴 방지는 발 이외 접촉(`forbidden_collision`) 종료가 담당 |
| 자세(orientation)는 움직이면 안 됨 | tilt 60°에서만 종료(사실상 낙상 감지) | `projected_gravity_sigma=0.10`(≈5.7°)의 강한 비용 + roll/pitch **각속도** 비용 + tilt **15°** 종료 |

측정된 zero residual 기준 모션의 최대 tilt는 전 속도 구간에서 1.6~4.4°이므로,
15° 종료는 낙상 감지가 아니라 **여유를 둔 실제 제약**이다.

## 2. 기준 모션 보정 (측정 기반)

flat, Standard stance(240/255), 명목 동역학, residual 0, 명령 고정 6초 유지,
앞 1.5초는 과도구간으로 제외하고 측정했다.

### 2.1 stride가 속도를 만든다 (cadence는 아니다)

`vx=0.50` 명령, lift 20°:

| stride | 1.0 Hz | 1.4 Hz | 2.0 Hz | 2.6 Hz | 3.2 Hz |
| ---: | ---: | ---: | ---: | ---: | ---: |
| 20° | 0.087 | 0.101 | 0.104 | 0.097 | 0.086 |
| 30° | 0.137 | 0.150 | 0.140 | 0.130 | 0.117 |
| 40° | 0.181 | 0.187 | 0.158 | 0.158 | 0.137 |
| 50° | 0.168 | 0.209 | 0.176 | 0.169 | 0.155 |

속도는 stride에 거의 비례하고 **cadence 1.4 Hz 이상에서는 오히려 느려진다.**
따라서 v3의 cadence는 1.20~1.50 Hz만 사용하고 속도 조절은 stride가 담당한다.

### 2.2 stride가 길면 clearance도 커져야 한다

| stride | lift 10° | lift 20° | lift 30° | lift 40° |
| ---: | ---: | ---: | ---: | ---: |
| 20° | 0.042 | **0.101** | 0.093 | 0.088 |
| 40° | 0.079 | **0.187** | 0.146 | 0.131 |
| 60° | — | 0.221 | 0.200 | **0.249** |
| 85° | — | 0.229 | 0.249 | **0.324** |

20° 부근까지는 clearance ≈ stride, 그 이상에서는 stride의 약 0.47배가 최적이다.
`lift = min(40°, max(0.47·stride, min(20°, stride)))`가 이 관측을 그대로 인코딩하며,
idle에서는 stride가 0이므로 발을 전혀 들지 않는다.

### 2.3 속도→stride 역산표

`lift` 법칙을 적용한 뒤 stride를 고정하고 측정한 값이다.

| stride | 10° | 15° | 20° | 25° | 30° | 40° | 50° | 70° | 80° | 90° |
| ---: | ---: | ---: | ---: | ---: | ---: | ---: | ---: | ---: | ---: | ---: |
| m/s | 0.020 | 0.067 | 0.101 | 0.131 | 0.154 | 0.192 | 0.203 | 0.242 | 0.301 | 0.336 |

곡선이 저속에서 급하고 중간에서 평평해지므로 **단일 gain으로는 추종할 수 없다**
(gain 하나로 맞추면 0.10 m/s에서 35% 초과, 0.30 m/s에서 미달). 그래서
`WalkConfig.stride_calibration`에 이 표를 넣고 역보간해서 stride를 얻는다.
회전도 같은 방식으로 `yaw_stride_calibration`을 사용한다(개루프 1.66 rad/s까지).

### 2.4 보정 후 명령 추종 (residual 0)

| 명령 | stride | 실제 | 추종률 | tilt |
| --- | ---: | ---: | ---: | ---: |
| `vx=0.05` | 13.2° | 0.050 | 100% | 1.0° |
| `vx=0.10` | 19.9° | 0.101 | 101% | 1.7° |
| `vx=0.20` | 47.3° | 0.206 | 103% | 2.5° |
| `vx=0.30` | 79.8° | 0.299 | 100% | 4.2° |
| `vx=0.40` | 90.0°(상한) | 0.336 | 84% | 4.4° |
| `vx=0.60` | 90.0°(상한) | 0.336 | 56% | 4.4° |
| `vx=-0.15` | 29.1° | -0.149 | 100% | 1.8° |
| `yaw=0.30` | 13.4° | 0.312 | 104% | 0.6° |
| `yaw=0.60` | 29.6° | 0.603 | 100% | 0.8° |
| `yaw=0.90` | 45.5° | 0.941 | 105% | 1.1° |
| `vy=0.08` | 0° | 0.000 | **0%** | 0.0° |

v1은 `vx=0.30` 명령에 0.06~0.10 m/s로 답했다. v3는 0.336 m/s(관절 여유 한계)까지
명령을 그대로 따라가고, 그 위에서는 포화되지만 **명령을 거부하지 않는다.**
남은 요구량은 residual이 만들어야 하며, 단측 보상이므로 못 만들어도 벌점은 없다.

## 3. 보상함수

제어주기 `dt = 0.02 s`가 모든 항에 곱해진다. **정지 상태의 idle 명령은 정확히 0점**
이다(생존 상수 없음 — docs/21 §11.2의 실패 원인 제거).

```text
c        = 평면 명령,  v = 몸체 평면 속도
progress = v · ĉ                     (명령 방향 성분)
drift    = ||v - ĉ·progress||        (명령 직교 성분)

speed  = +3.0 · min(progress, ||c||) / 0.30      ← 단측: 초과에 벌점 없음
drift  = -1.0 · drift / 0.30
yaw    = +1.0 · min(ω·sgn(ω*), |ω*|) / 0.90      ← 같은 단측 구조
```

`min()`이 속도 상한을 없애는 핵심이다. 명령보다 빠르면 **더 얻지도, 잃지도 않는다.**
v1/v2의 대칭 `exp(-||v-c||²/σ²)`는 초과를 벌했기 때문에 명령이 곧 상한이었다.

자세 비용(고정해야 하는 축):

```text
upright        = -1.50 · min(25, ||gravity_xy||² / 0.10²)
attitude_rate  = -0.30 · ((roll_rate/0.60)² + (pitch_rate/0.60)²)
heading        = -0.50 · (1 - yaw_gate) · min(25, (heading_err/0.25)²)
```

`heading`은 **직진 유지 목표**다. yaw 명령이 `0.05 rad/s`를 넘으면 목표 heading을
현재 몸체 heading으로 재고정하고 비용도 끈다. 이 처리 전에는 회전 명령에서 rate
오차가 적분되어 `yaw=0.9` 명령의 return이 -31.7까지 내려갔다.

수직 항은 없다. 높이·수직속도는 자유이며, `attitude_rate`에도 `vz`가 들어가지 않는다.

나머지: `inactivity`(전진/회전 중일 때만 켜지는 유휴 다리 벌점), `slip`,
`joint_limit`, `action_rate`, `action_magnitude`(0.25 → **0.02**; v1의 값은 다리를
쓰지 않는 쪽에 직접 보상을 줬다 — docs/17 §3), `current`, `idle_velocity`,
`idle_action`, `collision`, `termination`(-5).

### 3.1 종료 조건

| 조건 | v1 | v3 |
| --- | --- | --- |
| 비유한 상태 | 종료 | 종료 |
| tilt | > 60° | **> 15°** |
| 높이 낙하 | > 0.12 m 종료 | **없음** |

## 4. 관측·행동과 체크포인트 라우팅

관측 76차원 = v1의 70차원 + **발 접촉 6**. 접촉 정보는 docs/17 §3의 P3-10 처방이며,
동시에 체크포인트가 스스로를 식별하게 한다.

| 폭 | 학습기 |
| ---: | --- |
| 68 / 70 | `walk_learn` |
| 76 | `walk_v3` |
| 82 | `walk_v2` |

`policy_compat.task_for_observation_shape()`가 유일한 판정 지점이고, 로컬 재생·원격
실시간 중계·조이스틱 조종이 모두 이 함수를 거친다. 명령 정규화 분모는
`[0.40, 0.20, 0.90]`이며 **관측이 1.0을 넘을 수 있다**(명령을 clip하지 않기 때문).

행동은 18차원 residual, 범위는 ID 1~6 ±15°, 7~12 ±18°, 13~18 ±20°다. 기준 stride가
수십 도이므로 residual도 gait를 다시 쓸 수 있을 만큼 커야 한다. 최종 관절 목표는
기본 자세 ±70°로 제한한다 — 이는 **속도 제한이 아니라 관절 가동 한계**이며,
model.xml에 기계적 관절 범위가 아직 없어서 유지하는 보수적 값이다.

## 5. PPO 설정

v2에서 가져온 것은 **행동 분포 수정**뿐이다: gSDE + squashed policy이므로 PPO가
환경에 실제로 들어가는 bounded action의 log probability를 계산한다. 이 수정 없이는
raw action 성분의 84~95%가 clip에 붙어 있었다(docs/21 §10.2).

| 항목 | 값 |
| --- | --- |
| net | `pi/vf [256, 256]` |
| learning rate | 2e-4 |
| n_steps / batch | 512 / 512 (num_envs 무관하게 나눠짐) |
| n_epochs | 4 |
| gamma / gae_lambda | 0.995 / 0.95 |
| target_kl | 0.03 |
| use_sde / sde_sample_freq | True / 4 |
| log_std_init | -2.0 |

**정지 기준 승격**: `FixedCommandEvalCallback`이 idle, `vx=0.10/0.20/0.30/0.60`,
`vx=-0.15`, `vy=0.08`, `yaw=0.60`을 명목 로봇에서 재생해 zero residual 기준선과
비교한다. `best_model.zip`은 **기준선보다 점수가 높고, 기준선이 성공한 축에서
방향을 틀리지 않을 때만** 갱신된다. 하드코딩 기준 모션은 lateral 방향을 만들지
못하므로 "방향 실패 0"을 절대 조건으로 두면 승격이 구조적으로 불가능해진다.

## 6. 실행

런처(`python SCONE.py` → RL)에서 `걷기 정책 v3`를 선택하면 로컬/원격 학습, 일시정지,
재개, 실시간 중계, 재생이 기존 작업과 동일하게 동작한다. 직접 실행:

```bash
# 기준 모션과 보상을 한 rollout로 확인 (학습 없음)
PYTHONPATH=. python -m src.rl.walk_v3 --stance standard check --command 0.30 0 0 --steps 300

# 학습
PYTHONPATH=. python -m src.rl.walk_v3 --stance standard train \
    --curriculum easy --timesteps 20000000 --num-envs 8

# 재생 (viewer)
PYTHONPATH=. mjpython -m src.rl.walk_v3 enjoy runs/walk_v3/best_model.zip --command 0.30 0 0
```

명령 curriculum은 easy `0.20`, medium `0.30/0.05/0.50`, full `0.40/0.12/0.90`이다.
전 단계가 기준 모션의 실측 상한(0.336 m/s) 안팎이므로 v1처럼 명령이 능력의 6배가
되는 상황은 없다.

## 7. 남은 한계

1. **lateral scaffold 없음.** 하드코딩 기준 모션은 `vy` 명령에 0.000 m/s로 답한다.
   좌우 이동은 전부 residual이 만들어야 하고, 평가 suite는 이 격차를 그대로
   측정한다. IK 기반 `tripod-gait`는 방향은 맞지만 stride 상한이 v3가 없애려는
   속도 천장이므로 v3의 선택지에서 제외했다.
2. **몸체 +x가 전방인지 미확정.** v3는 v1의 chassis frame 규약을 그대로 쓴다
   (docs/17 §3 각주, docs/18 참고). 내부 일관성은 검증됐다 — `+vx` 명령은 측정
   속도 `+vx`를 만든다.
3. **관절 하드스톱 미측정.** ±70° 목표 제한은 측정값이 아니라 보수적 가정이다.
   실측하면 이 값이 v3의 실질 최고 속도를 다시 정한다.
4. **좌우 대칭 강제 장치 없음.** v2의 mirror 증강은 v3에 넣지 않았다(v2에서
   실패를 되돌리지 못했고, 관측 레이아웃별 sign 처리 위험만 늘린다).
