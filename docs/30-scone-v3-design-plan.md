# MARC v4 설계·검증 실행 명세 rev.4

개정일: 2026-09-09 · 대상: **실물 기구 MARC v4**

**명칭.** 이 기체를 한 줄로 쓰면 **부채꼴(호) 모양 바퀴로 굴러가면서 걷고 계단을 오르는 다족 로봇**이다.
그 한 줄을 그대로 줄인 것이 이름이다.

**MARC = Multi-legged Arc-wheel Rolling Climber** (확정).

| 글자 | 단어 | 담는 것 |
|---|---|---|
| M | Multi-legged | 다족. 개수를 말하지 않으므로 6족 v1~v3과 4족 v4를 함께 덮는다 |
| A | Arc-wheel | 부채꼴(호) 모양 바퀴 — 이 기체의 핵심 기구 |
| R | Rolling | 주행 (굴림) |
| C | Climber | 계단 이동 |

출발점은 "Multi-legged robot driven by ARC-shaped wheel (or frame)"이었고, 남는 R·C에 주행과
계단을 넣어 네 글자를 모두 뜻이 있게 만들었다. 함께 검토한 ACRA·ARCRA는 쓰지 않는다.
ARCRA는 R이 겹쳐 읽기 불편하고 ACRA는 다른 기관 약어와 겹친다.

**계보.** MARC는 기존 SCONE 전체를 포함하는 계열 이름이다. 다리 수가 6에서 4로 바뀌어도 부채꼴
바퀴로 주행·보행·계단 이동을 하는 원리는 같으므로 세대를 끊지 않고 이어간다.

| 기존 명칭 | 새 명칭 | 내용 |
|---|---|---|
| SCONE v1 | MARC v1 | 6족 최초 기체. 부채꼴 회전축이 다리 중심과 어긋남 |
| SCONE v2 | MARC v2 | 6족. 축 정렬 수정, ㄷ자 개단면 프레임 (파손·흔들림 발생) |
| SCONE v3 (rev.1~3) | MARC v3 | 6족 설계안. CAD 미생성, 문서 단계에서 종료 |
| — | **MARC v4** | **4족. 본 문서의 대상** |

v3는 문서만 있고 실물이 없으므로 v4는 v2 실물과 v3 설계 결정을 함께 승계한다. 저장소 경로
`~/Developer/SCONE`, 기존 파일 이름, MuJoCo 자산 이름처럼 이미 기록으로 남은 식별자는 이번
개정에서 바꾸지 않는다. 개명 적용 범위는 §19.3에 적는다.

이 문서는 다른 에이전트가 작업 순서, 형상 정의, 입력 자료, 합격 기준과 실패 처리를 임의로 정하지
않고 진행하기 위한 명세다. **현재 완료 상태는 설계 문서 개정이며, CAD 생성·구조 해석·실물 제작이
완료된 상태가 아니다.** 미확인 부품 치수나 성능을 가짜 확정값으로 채우지 않는다.

- **D0: 검증용 디지털 후보** — 아래에 정의한 형상과 좌표로 바로 구현한다. 질량·간섭·접지 가정을 검증하는 모델이며 출력용 부품이 아니다.
- **D1: 제작 후보** — 실제 부품 도면·체결·출력 조건을 반영해 제작 검증을 받는 모델이다. D0를 이름만 바꿔 D1로 취급하지 않는다.
- **RELEASE: 제작 확정** — §15의 제작 관문이 모두 통과한 리비전에만 부여한다.

§10의 JSON은 입력 수치의 원천, §11은 좌표와 관절의 원천, §14는 실행 순서, §15는 판정 규칙이다.
다른 표의 반올림 수치를 다시 입력하지 않는다. 여기서 정한 D0 기본 선택은 이번 개정의 **검증을 위한
설계 결정**이며 최적해나 실측값이 아니다.

### 0.4 유지하는 방향과 철회한 결론

유지: 구조재 PLA, 타이어 TPU 95A, 폐단면 링크, 림 양측 립, 방사 리브, 부채꼴 양단 지지,

실물 변형 3.69→0.15mm, v3 실물 heave 14mm, 회전당 전진 481mm, 확정 총질량 4.569kg.

**rev.3에서 추가로 철회하는 것:**
- **"부채꼴 4개로는 최소 2점 접지"** — 틀렸다. 몸체가 기울면 항상 3점이다. 위상이 정하는 것은
  접지 개수가 아니라 기울기 크기다. 그래서 **접지호를 270°로 키우자는 rev.3 검토 제안도 무효**다.
- **"조향축 스윙반경 182.5mm 때문에 전방 굴림이 불가능"** — 틀렸다. 진행 방향은 다리가 뻗는
  방향이며 조향 없이 굴러간다. 이 결론은 "전방 = 몸통 장축"이라는 잘못된 전제에서 나왔다.
- **"role-split 보행이 필수"** — v2의 부채꼴 장착 헤딩이 다리마다 달라서 필요했던 우회책이다.
  v3/v4는 네 부채꼴이 모두 같은 방향이므로 전부 동시에 굴린다.

**현재 판정: D0 구현을 진행한다. 전체 기체 제작 치수 확정은 보류한다.**

## 2. 접지 프로파일과 접촉 계산

### 2.1 프로파일 좌표의 유일한 정의

부채꼴 자체 좌표를 `(u,v,w)`로 두고 판은 u–w 평면, 축방향은 v다. 각도 `chi=0`은 +u, 양의 chi는 +u에서 +w로 향한다. **개구는 -u 방향**이며, 각도는 `[-157.5°, +157.5°]`의 재료 구간으로 저장한다. 전역 방향은 §11의 변환으로만 정한다.

```text
chi_tread_end = th_tread/2
chi_material_end = chi_tread_end + d_lobe
rho_t(chi) = R_tread                                      if abs(chi) <= chi_tread_end
rho_t(chi) = R_tread - k_ramp*(abs(chi)-chi_tread_end)      그 밖의 재료 구간
k_ramp = (R_tread-r_lobe_tip)/d_lobe                      [mm/deg]
rho_s(chi) = rho_t(chi)-t_tire                            PLA 외곽
rho_r(chi) = rho_s(chi)-t_rim                             림 내곽
rho_l(chi) = rho_r(chi)-h_lip                             립 내곽
point(r,chi,v) = (r*cos(chi), v, r*sin(chi))
```

기본값에서 타이어 팁/PLA 팁/림 내곽 팁/립 내곽 팁은 각각 **112.5/102.5/99.5/87.5mm**다. 로브에서도 림 두께 3mm와 립 반경 깊이 12mm가 유지된다. 이는 **반경 방향 두께 정의**이며 곡선 법선 방향 등두께와는 다르다. 법선 최소 두께는 최종 형상 검사에 포함한다.

### 2.2 D0 형상 생성 규칙

D0는 불명확한 스플라인·팁 필렛·허니컴을 사용하지 않는다.

1. chi를 시작점부터 끝점까지 `profile_step_deg=0.5` 간격으로 샘플링한다. 양 끝과 ±112.5° 경계를 반드시 포함한다.
2. 각 반경 곡선을 동일 chi 배열의 점으로 만든다. 인접점은 직선으로 잇는다. 폐곡선은 외곽을 정방향, 내곽을 역방향으로 연결한다.
3. 이 다각형을 §3의 v 구간으로 압출한다. 자체 교차, 음수 면적, 0 두께, 실패한 boolean이 하나라도 있으면 B03 실패다.
4. D0에서 `nose_fillet_mm=0`, 웹 포켓 제거율 0, 링크 경량화 홀 제거율 0으로 고정한다. rev.2의 R12 필렛·72% 포켓·25% 경량화는 아직 검증되지 않은 후속 후보다.
5. 최종 D1에서 필렛/포켓을 추가하면 별도 후보 ID를 만들고 프로파일·질량·강성·간섭 검사를 모두 다시 수행한다. 생성 실패 시 필렛 반경을 몰래 줄이거나 형상을 자동 치유해 통과시키지 않는다.

이 선택은 제작 완성도를 주장하기 위한 단순화가 아니라, 같은 수학 형상이 CAD와 계산에 들어가도록 만드는 재현 가능한 기준이다.

### 2.3 지지점과 heave 계산

지면 법선 `n`을 위쪽 단위벡터로 두고, 현재 부채꼴 자세로 변환한 모든 표면점 `r_k(q)`에 대해 계산한다.

```text
h(q,n) = -min_k dot(n, r_k(q))
contact_candidates = { k : dot(n,r_k) - min_j dot(n,r_j) <= support_tol_mm }
p_contact = p_axle + r_k(q)                              접촉 후보별 저장
heave = max_q h - min_q h
```

D0의 평면 프로파일 검사는 chi 0.5°/회전 q 0.5°로 시작하고 둘 다 절반 간격으로 반복한다. heave 변화 <0.05mm이면 수치 수렴으로 판정한다. 접점이 여러 개인 경우 첫 점 하나를 임의 선택하지 않고 모두 반환한다. 실제 접촉 패치와 반력은 이후 강체/접촉 해석에서 결정한다.

필렛 전 연속 프로파일의 회귀 기준은 heave **33.2477mm**, 팁 사이 현 길이 **136.9713mm**다. 이 값은 실물 진동이나 계단 성능의 합격값이 아니다. `r_nose=12mm` 적용 후에도 같다고 가정하지 않는다.

### 2.35 개구각의 결정과 heave에 대한 정정

**정정.** rev.4까지 "나선 로브가 heave를 75.6mm에서 18.56mm로 줄였다"고 썼는데 이는 틀렸다.
heave는 로브의 유무가 아니라 **개구각과 팁 반경**으로 정해진다.

```text
heave = R_tread - r_lobe_tip * cos(개구각/2)
```

같은 개구각이면 램프(로브)가 있는 쪽이 팁 반경이 작아 heave가 오히려 커진다. 확인값:

| 형상 | 개구각 | heave |
|---|---:|---:|
| 로브 45°, 팁 112.5 | 45° | 18.56 mm |
| 램프 없음, 팁 122.5 | 45° | **9.32 mm** |
| v2 (램프 없음) | 135° | 75.62 mm |

75.6 → 18.56은 개구각을 135°에서 45°로 줄인 효과였다. **로브의 실제 효용은 heave 감소가 아니라
① 접지 모서리 충격 완화 ② 계단 걸이용 뾰족한 팁 두 가지다.** 이 두 가지 때문에 로브 45°는 유지한다.

**개구각을 75°로 정한 근거.** rev.4의 45°는 재료가 315°를 덮어 부채꼴이라기보다 노치 낸 바퀴였다.
heave 최소화만 목적함수로 두고 개구각에 하한을 걸지 않은 결과다. 제약을 명시하면 다음과 같다.

1. **접지호 >= 180°** (하드). 이 조건에서만 §7.4의 대각짝 위상이 몸통 상하동요를 정확히 0으로 만든다.
   로브 45°를 유지하면 개구각 상한은 `360 - 180 - 90 = 90°`다.
2. **굴림 중 몸통 기울기**. 기울기는 heave에 비례한다. 피치 `atan(heave/465)`, 롤 `atan(heave/320)`.
3. **목 너비** `2*r_lobe_tip*sin(개구각/2)` — 계단 모서리를 물 수 있는 입 크기.

| 개구각 | 접지호 | heave | 피치 | 롤 | 목 너비 | 스핀 관성비 |
|---:|---:|---:|---:|---:|---:|---:|
| 45° (rev.4) | 225° | 18.56 | 2.29° | 3.32° | 86.1 | 1.000 |
| 60° | 210° | 25.07 | 3.09° | 4.48° | 112.5 | 0.950 |
| **75° (채택)** | **195°** | **33.25** | **4.09°** | **5.93°** | **136.97** | **0.900** |
| 90° (상한) | 180° | 42.95 | 5.28° | 7.64° | 159.1 | 0.851 |

75°를 채택했다. 목 너비가 1.6배가 되고 스핀축 관성이 10% 줄어 §15의 관성 목표 초과가 해소된다.
굴림 기울기는 q1으로 상쇄할 수 있으나 공짜가 아니다: 상쇄에 필요한 β 스윕은 개구각 45°에서 ±15.9°,
75°에서 ±28.5°, 90°에서 ±36.8°다.

### 2.4 이동거리와 계단 치수

- `2πR×195/360=416.916mm`의 이름은 **일정 반경 접지호 길이**다. (개구각 75° 채택 전에는 225°/481.056mm였다.)
- 완전 1회전의 이상적 무미끄럼 이동거리는 모든 접지 상태를 포함해 계산한다. 지지함수 적분의 기준값은 약 739.54mm/rev이며, 이 또한 실물 주행 예측값은 아니다.
- 실물/시뮬레이션 이동거리는 몸체 위치 차이, 속도 적분, 접촉 미끄럼을 함께 기록한다.
- throat 80mm, 팁 반경 감소 8mm, 계단 높이 200mm는 기존 계획에서 계승한 **후보 목표**다. 실제 계단 디딤판·코 반경·마찰·접근 자세는 I09에 별도로 필요하다.
- 순수 기하 heave에 v2 실측/기하 비율 0.767을 곱하는 예측은 사용하지 않는다.

### 3.2 D0 타이어 형상과 질량

`rho_s <= r <= rho_t`, v=`[-b_sector/2,+b_sector/2]`의 방사 밴드를 별도 바디로 생성한다. D0는 공극을 만들지 않은 접촉 외형이며 실효밀도 0.494g/cm³를 **예비 질량에만** 사용한다. TPU 강성은 이 밀도로 추정하지 않는다.

D1은 실제 셀·외피·타이어 고정 방식과 출력 재료 벌크 밀도를 사용한다. 허니컴을 직접 만들면서 0.494를 다시 적용하는 이중 공극 차감은 금지한다. 셀 정의·벌크 밀도·끼움 공차가 없는 동안 D1 타이어는 BLOCKED(I03/I04)다.

### 3.3 반력 계산

`mg/N`은 평균 참고값이다. 설계 하중은 실제 접촉점과 CoM에 대해 다음 정적 평형을 풀어 얻는다.

```text
sum(F_i) + m*g_vector = 0
sum((p_i-p_COM) cross F_i) = 0
N_i = dot(F_i,n_i) >= 0
norm(F_tangent_i) <= mu_i*N_i
```

4족은 지지 상태가 세 가지로 나뉘며 각각 다른 성질을 갖는다.

| 지지 상태 | 접지 다리 | 반력 결정 | 정적 안정 |
|---|---|---|---|
| 4점 (굴림·정지) | 4 | **과구속.** 3자유도에 구속 4개 → 반력이 유일하지 않다 | 마진 크다 |
| 3점 (크롤 스윙) | 3 | 3×3 선형계로 유일 | **직사각형 배치에서 CoM이 정중앙이면 마진 0** |
| 2점 (트롯) | 2 대각 | 정적 평형 불성립 | 동적 제어 필수 |

- **4점**: 잉여 구속 1개다. 자동차와 같은 정정 초과 상태이며 타이어 컴플라이언스가 배분을 정한다.
  구조 입력으로는 정적 선형/원뿔 제약 안에서 각 `N_i`의 **최댓값**을 구해 보수적으로 쓴다.
  균등 분배(`mg/4`)를 자동 선택하지 않는다.
- **3점**: 유일해가 나온다. 음수 반력은 지지 상태 불성립으로 FAIL 처리한다.
- **2점**: 정적 해가 없다. 반력은 동역학 로그에서만 얻는다. **구조 입력으로 쓸 때는 `mg/2`를
  보수적 상한으로 표시**하고 실제 트롯 하중은 I07 측정으로 대체한다.

D0 회귀 예제: 접점 `(232.5,-160),(232.5,160),(-232.5,160),(-232.5,-160)`, CoM=(0,0).
4점 균등 가정에서 각 `8.87N`, 한 다리(앞우)를 든 3점에서 나머지 셋의 분담은
**`0 / 50 / 50 %`가 아니라 `50 / 0 / 50 %`도 아닌 경계 해**이며 CoM이 지지 삼각형의 빗변 위에
정확히 놓인다. 이 좌표는 회귀 예제이며 rev.4 실제 접점은 §11에서 재생성한다.

### 3.4 하중 케이스와 구조 판정

`N_ref`는 검증한 자세·CoM·지지 패턴 전체에서 해당 다리의 최대 정적 반력이다. 해당 값이 없으면
예비 스크리닝에만 `m_upper*g/3`을 사용하고 보수적 상한이라고 표시한다. 아래 배수는 3~5배 하중
요구를 구체화한 **준정적 검사 케이스**이며 실제 착지 충격을 측정했다는 뜻이 아니다.

| ID | 입력 | 경계조건 및 출력 |
|---|---|---|
| LC01 | 실제 정적 지지 반력과 모든 부품 자중 | 조립체 관절 반력·변위·응력 |
| LC02 | 접지점 수직 `5*N_ref` | 단일 다리 stage-1 장착면 고정, 전체 하중 경로 |
| LC03 | 접지점 ±축방향 `3*N_ref` | 부채꼴·포크·링크 각각과 조립체의 같은 방향 변위 |
| LC04 | 접지점 ±축방향 `5*N_ref` | 출력 방향별 강도·체결부·국부 응력 |
| LC05 | stage-2 실제 전류 제한에서의 최대 출력 토크 | 허브–리브–림 하중 경로, 혼·볼트군·스터브 |
| LC06 | 양쪽 로브 팁 각각에 `3*N_ref` | 수직 및 ±접선 방향을 별도 해석. **접촉면이 TPU 모서리**임을 명시하고 국부 접촉응력·마모를 함께 본다 |
| LC07 | 실제 정지 유지 하중 | 온도·시간을 포함한 크리프 시험 |
| **LC08** | **트롯 착지: 대각 2점에 각 `mg/2` + 수직 충격 3배** | **4족 고유. 6족에는 없던 케이스. 링크 굽힘·클레비스·허브** |

**LC02(반경 방향) 국부 검토** — 리브 간 스팬 88.4 mm, 고정-고정 근사 `M = F·s/8`:
`N_ref = 11.82 N`에서 `M` = 653 N·mm, 반경 방향 단면계수 `Z_rad` = 565 mm³ →
σ = **1.16 MPa, SF 41**. **반경 방향은 지배 하중이 아니다.** 지배는 LC03/LC04(면외)다.

LC05의 실제 제한값이 없으면 12V stall 3.0N·m를 **예비 구조 입력**으로만 쓴다. 정상 운전 허용치로
쓰지 않는다.

- PLA E=3200MPa, 강도 48MPa, G=1230MPa는 예비 해석 입력이다. 제작 판정에는 I04의 동일 출력
  조건·방향별 실험 자료를 사용한다.
- 강도 후보 목표는 SF≥4, LC03 부채꼴 변위≤0.53mm, 링크 비틀림≤0.10°다. 현재 후보가 통과했다는
  뜻이 아니다.
- 변위를 같은 힘·좌표·경계조건으로 비교한다. 백래시의 무부하 간극을 탄성 변형과 단순 합산해
  '강성 개선 불필요'로 결론 내리지 않는다.
- 메시를 세분해 변위와 특이점에서 떨어진 응력이 각각 5% 이내로 수렴하는지 기록한다.
- 인서트가 있어도 PLA 보스 인발·압궤·회전·크리프를 검사한다. SF<요구값과 실제 파단을 구분한다.

**4족 전환으로 하중이 줄어든 결과** (`N_ref` 14.94 → 11.82 N, −21%). 부채꼴 단면을 그대로 두면
안전율이 올라간다. **D0는 단면을 줄이지 않고 여유를 남긴다.** 경량화는 §15의 관문을 통과한
기준 부품을 만든 뒤 별도 후보로 진행한다.

**면외 단면 정의.** 축방향(±v) 힘에 대한 저항 단면은 림(두께 `t_rim`=3, 축방향 폭 `b`)과 양측
립(높이 `h_lip`=12, 두께 `t_lip`=3)으로 이루어진 ㄷ자다. 중립축은 축방향 중앙이고 최외단 거리는
`b/2`다. **모멘트 팔과 캔틸레버 길이는 서로 다르며 둘 다 명시한다.**

```text
I  = t_rim*b^3/12 + 2*( h_lip*t_lip^3/12 + h_lip*t_lip*((b-t_lip)/2)^2 )
Z  = I/(b/2)
Lm = R_tread - r_hub = 100.5      # 접지면에 힘이 걸릴 때 허브 뿌리의 모멘트 팔
Ld = r_lobe_tip - r_hub = 90.5    # PLA 판 자체의 캔틸레버 길이 (변형 계산용)
sigma = 5*N_ref*Lm/Z              # SF = 48/sigma
delta = 3*N_ref*Ld^3/(3*E*I)
```

| b | h_lip | 면외 I | 면외 Z | 변형 @3×N_ref | SF @5×N_ref | 판정 |
|---:|---:|---:|---:|---:|---:|---|
| **20** | **12** | **7256 mm⁴** | **725.6 mm³** | **0.377 mm** | **5.86** | **D0 채택 (여유 보존)** |
| 18 | 12 | 5562 | 618.0 | 0.492 | 4.99 | 경량화 후보 |
| 16 | 12 | 4120 | 515.0 | 0.665 | 4.16 | 변형 목표 초과 |
## 4. 회전축·포크·허브 조립

### 4.1 D0 포크와 모터 포락

내폭 `b_sector+2*clevis_gap=24mm`, 팔 두께 5mm, 포크 바깥 폭 34mm는 **판과 포크만의 D0 후보값**이다. 모터 몸체·혼·나사머리·베어링 고정부·배선의 전체 축방향 폭은 포함하지 않는다.

D0 포크 좌표는 stage-2 축 중심을 원점으로 하고 크랭크 두 번째 구간의 길이 방향을 e, v를 축방향, `f=e cross v`를 높이 방향으로 둔다. e는 §11의 `cos(q1+gamma)*u_i+sin(q1+gamma)*w`다. 포크의 **도달 길이는 22mm가 아니라 `R_tread + 2 = 124.5mm`** 다. 부채꼴은 stage-2 축을 중심으로 반경
122.5mm의 원판 전체를 쓸고 지나가므로, 그 원 안에 있으면서 축방향 `|v| <= 10`인 링크 재료는 회전 중
반드시 부딪힌다. 따라서 클레비스는 다음 한 줄로 정의한다.

```text
크랭크 링크에서 stage-2 축을 중심으로 반경 124.5mm, |v| <= b_sector/2 + clevis_gap = 12mm 인
원기둥을 빼낸다.  ->  남는 팔 두 개는 |v| 12..17mm, 즉 clevis_arm_t = 5mm 와 정확히 일치한다.
```

D0 구현 결과: 제거 체적 16.708 cm³, 링크 질량 86.433 g → **66.718 g**. 이 절삭 후 링크–부채꼴,
링크–타이어 교차가 0이 된다. 브리지는 e=`[-27,-22]`, v=`[-17,17]`, f=`[-22,22]mm` 박스로 정의한다.
링크 끝 27mm 구간과 브리지의 겹침은 미해결 접합 영역으로 표시한다.

**팔이 길어지면 비틀림 강성이 떨어진다.** 다만 팁에서 축·베어링이 두 팔을 다시 이어 주므로 닫힌
경로가 되며, 이것이 v1/v2의 외팔 지지를 클레비스로 바꾼 이유다. 실제 비틀림 강성은 축·베어링
사양이 정해진 D1에서 LC03/LC04로 확인한다. 정확한 모터 체결·베어링 지지는 I02 도면을 확보한 D1에서만 만든다. 포락을 실제 조립체로 집계하거나 이 겹침을 제작 무간섭으로 통과시키지 않는다.

XM430의 28.5mm를 회전축 방향 크기라고 가정하지 않는다. 도면/STEP의 기준면에서 몸체·혼·케이블 플러그를 포함한 실제 포락을 측정한다. D0 포락만 있는 모터는 질량용 블록과 실제 충돌 검증용 부품을 구분한다.

D0에서 제조사/기존 모터 CAD와 축 변환이 확보되면 그 형상을 사용한다. 없으면 해당 축에 좌표 마커만 놓고 `geometry_status=MISSING`으로 기록한다. 모터가 없는데 전체 간섭 PASS를 내지 않는다. MX-28AT 77g, XM430 두 종류 각 82g은 데이터시트 참고 질량으로 기록하되, CoM/관성이 없으면 null이다. 그때 구조 부품만의 질량 부분합과 누락 모터 개수를 따로 출력한다. 도면 없이 모터 크기·축 오프셋을 추측한 블록은 생성하지 않는다.

### 4.2 D1 허브를 생성하기 위한 필수 자료

I02에는 혼 부품번호/리비전, 도면 PDF 또는 STEP, 중심 체결과 주변 볼트의 지름·좌표·깊이, 혼 중심축/장착면, 베어링 정확한 품번, 스터브와 빠짐 방지 단면을 넣는다.

1. 혼 장착면을 축방향 기준 0으로 정한다.
2. 모터–혼–PLA 허브–스터브–베어링–포크의 단면을 실제 치수로 배치한다.
3. 혼 수용부는 필요한 깊이의 포켓으로 정의한다. **Ø19.5 관통홀은 기본값에서 삭제**한다.
4. 주변 체결 구멍은 제조사 좌표에서 가져온다. **2026-09-09 검수에서 기존 `SCONEv3 v8` Fusion 파일의
   실제 체결 형상을 측정해 아래를 확정했다.** 이 값은 추정이 아니라 형석 본인이 만든 조립체에서
   뽑은 것이다.

6. 반대쪽 Ø10 시트가 필요한 경우 앞쪽 포켓과의 잔여 벽을 별도 치수로 검증한다. 베어링 10×19×5mm는 품번 확인 전 포락 후보에 한정한다.

## 5. 링크·요크·프레임 구조

### 5.1 크랭크의 정의

```text
link_a=90mm, link_b=110mm, gamma=25deg
L_link = hypot(link_a+link_b*cos(gamma), link_b*sin(gamma)) = 195.307179mm
phi_off = atan2(link_b*sin(gamma),link_a+link_b*cos(gamma)) = 13.770009deg
```

같은 두 축 사이 거리의 단일 강체 링크는 끝점 기구학이 같다. 꺾인 부재의 응력·질량·간섭·관성까지 직선 보와 같다는 뜻은 아니다.

D0 링크는 길이축을 따라 a 구간 뒤 +w 쪽으로 gamma만큼 꺾이는 b 구간이다. 각 구간에 폭 v=34mm, 높이 37mm, 벽 2.8mm의 직사각 폐단면을 sweep하고 꺾임은 두 구간의 미터 접합으로 닫는다. 내부 공극도 같은 중심선으로 이어지게 만든다. 정확히 두 끝만 개방하고 D0에는 경량화·배선 구멍을 뚫지 않는다. 꺾임에서 자기 교차 또는 끊긴 벽이 있으면 FAIL이다.

요크 D0는 다음 표의 직육면체 외곽과 균일 벽 두께를 갖는 중공 박스다. 장착 구멍과 배선 홀은 D1 도면에 따른다. 중공 박스 양 끝을 닫는 캡도 같은 벽 두께로 만든다.

| 부분 | 길이×폭×높이 mm | 벽 mm | 배치 |
|---|---|---:|---|
| 요크 #1 | 44×33×26 | 3.5 | 조향축부터 바깥 u 방향, z 중심 0. **아래 경고 참조** |
| 요크 #2 | 41×31×24 | 3.5 | stage-1 축을 끝 기준으로 바깥/안쪽 연결 포락. **아래 경고 참조** |

**경고 — 이 두 포락은 담아야 할 모터보다 작다.** 실제 모터 형상을 D0에 넣고 나서 측정한 결과다.

| 요크 | 포락 (내림차순) | 담을 모터 | 모터 (내림차순) | 부족량 |
|---|---|---|---|---|
| 요크 #1 | 44.0 / 33.0 / 26.0 | MX-28AT (혼 포함) | 50.6 / 45.1 / 35.6 | **6.6 / 12.1 / 9.6 mm** |
| 요크 #2 | 41.0 / 31.0 / 24.0 | XM430 (혼 포함) | 46.5 / 42.4 / 28.5 | **5.5 / 11.4 / 4.5 mm** |

D1에서 요크를 다시 정할 때 최소 요구치는 `모터 외형 + 2*(벽 3.5 + 여유 1) = 모터 + 9mm/축`이다.
즉 요크 #1은 최소 **59.6 × 54.1 × 44.6**, 요크 #2는 최소 **55.5 × 51.4 × 37.5** 가 필요하다.
축 순서는 실제 장착 방향에 맞춰 다시 배정한다. 이 값을 확정 치수로 쓰지 말고 I02 도면으로 검증한다.

요크 #2의 D0 길이축은 u, 끝면 중심은 stage-1 축, 반대 끝은 안쪽 u 방향이다. **네 다리 모두 같은 요크를 쓴다.** 6족의 중앙 다리용 66mm 연장형은 삭제했다. #1과 #2는 union하지 않고 부품별 포락으로 둔다. 모터 장착부와 연결 체결이 없는 동안 구조 검증은 D1 관문에서 BLOCKED다.

### 5.2 해석식의 사용 범위

구멍 없는 직선 박스에만 다음 예비식을 쓴다. 단위는 N, mm, MPa다.

```text
A = w*h-(w-2*t)*(h-2*t)
I_v = (w*h^3-(w-2*t)*(h-2*t)^3)/12
Z_v = I_v/(h/2)
J_thin = 4*((w-t)*(h-t))^2 / (2*((w-t)+(h-t))/t)
twist_rad = T*L/(G*J_thin)
```

w34/h37/t2.8/L195의 비교값: `J≈97492.6mm^4`, `Z≈3797.13mm^3`, PLA 밀도 1.18에서 질량 **84.27g**. 63.2g은 25% 재료 제거를 가정했던 rev.2 값이다. 구멍을 낸 뒤 같은 J를 유지하지 않는다.

rev.2 평균하중 14.94063N을 넣은 회귀 예제에서 `5*Wi*195/Z≈3.84MPa`, `SF≈12.5`다. `3*Wi*122.5` 비틀림 모멘트의 링크 끝 접지점 변위는 약 1.094mm다. 이는 예비식의 회귀 기준이며 D1 강도·변형의 합격 증거가 아니다.

### 5.3 제작 조건

- 구조재 PLA 선택은 유지한다. 정확한 필라멘트·프린터·노즐·선폭·레이어·방향·온도·건조 조건은 I04에서 고정한다.
- 3.5mm를 0.4mm의 정확한 9겹으로 표현하지 않는다. 슬라이서 실제 선폭과 벽 충전 상태를 확인한다.
- 형상을 공극까지 직접 모델링했으면 재료의 벌크 밀도를 사용한다. infill 효과를 밀도와 CAD 공극 양쪽에서 중복 반영하지 않는다.
- 구조용 인서트의 외경·길이·파일럿 홀·삽입 공정은 실제 SKU 자료로 정한다. 모든 인서트를 Ø3.4×4mm로 통일하지 않는다.
- 경량화는 검증된 무공 기준 부품을 만든 뒤 진행한다. 질량과 하중별 강성을 같은 CAD 리비전에서 비교한다.
- 파손 원인과 강성 개선율은 동일 조건의 조립체 시험 결과가 생긴 뒤 서술한다.

## 6. 자세·토크·도달거리

### 6.1 기준 자세

원점과 관절은 §11에서 정의한다. 하부 프레임 기준 하면은 z=-18mm이며 H는 그 면에서 지면까지의
수직 거리다. 원호가 바닥을 지지하고 stage-1 축 높이가 0인 경우:

```text
z_ground = frame_bottom_z-H
z_axle   = z_ground+R_tread
beta     = asin(z_axle/L_link)                고도각
q1       = beta-phi_off                       실제 모델 stage-1 좌표
arm      = L_link*cos(beta)                   stage-1 축 -> 접지점 수평거리
```

D0 H=255에서 `z_ground=-273`, `z_axle=-150.5`, `beta=-50.406090°`, `q1=-64.176099°`,
`arm=124.477485mm`다. 로브/팁 접촉 시 R 대신 실제 지지 높이 h(q)를 넣고 접촉 상태와 함께 푼다.

D0는 절대 프로파일 각 `alpha_abs=0`인 기준 자세를 사용한다. §11의 정의에 따라 `q2=alpha_abs-q1`이다.
이 자세는 CAD와 수학의 비교용이며 최적 정지 자세가 아니다. **`alpha_park` 최적값은 미정(null)** 이다.

### 6.2 자세 모드 — 스파이더에서 개까지

**stage-1 축이 이미 몸체 횡축과 평행하므로 `beta` 하나로 sprawl(스파이더) ↔ parasagittal(개)
전환이 된다. 새 자유도가 필요 없다.** 이는 v3에서 확인했으나 정식 기능으로 정의하지 않았던 항목이며,
rev.4에서 운용 모드로 승격한다.

- 설계토크 = `2 * W_i * arm / 1000`. 계수 2.0 = **안전율 1.5 ÷ 외부 전달효율 0.75**다.
  0.75는 **혼 유격·베어링 마찰·케이블 저항 같은 관절 바깥의 손실**이며, 제조사 stall 값에 이미
  들어 있는 **내부 감속기 효율이 아니다**(§6.3). 같은 0.75를 두 번 적용하지 않는다.
  stall 4.1 N·m 대비 백분율.
- `W_i(3점)` = 11.82 N, `W_i(4점)` = 8.87 N, `W_i(트롯 2점)` = 17.73 N (m = 3.615 kg).
- 트롯 2점, 개 자세: 설계토크 **2.37 N·m (58%)**. **기준 자세에서 트롯을 하면 4.41 N·m(108%)로
  stall을 넘는다. 트롯은 `beta <= -60°`에서만 허용한다** (−60°에서 3.46 N·m, 84%).
- **스파이더 자세는 3점 지지에서 stall을 넘는다(102%).** 4점 지지 굴림 전용으로 제한하고,
  다리를 드는 동작은 `beta <= -40°`에서만 수행한다. 이 제한을 B10 검색과 제어기에 강제한다.
- 이 표는 준정적 계산이며 실제 운전 판정은 I07의 토크–속도/전류/열 자료가 필요하다.

**보행 속도는 개 자세가 더 빠르다.** 보폭은 `beta` 스윕이 만들고 `dx/dbeta = L*sin|beta|`이므로
다리가 설수록 같은 관절각에 발이 더 많이 움직인다.

|---:|---:|---:|---:|
| −50° | 150 mm/rad | 78 mm | 0.120 m/s |
| −70° | 184 | 95 | **0.146 m/s** |
| −80° | 192 | 100 | 0.154 m/s |

### 6.3 접지 토크 계산

원형 접지호를 돌리면 접촉하는 재료 점이 바뀐다. `x_contact=R*sin(alpha)`를 일반 접지식으로 사용하지
않는다. 최종 형상에서 §2의 지지점을 구한 뒤 관절별 요구 토크를 계산한다.

```text
a_j = 세계 좌표계의 관절 단위축
p_j = 관절축 위의 점
F_k = 해당 관절 아래 부품에 가해지는 외력, 중력 포함
tau_hold_j = -sum_k dot(a_j, (p_k-p_j) cross F_k)
```

stage-1에는 타이어 접촉력뿐 아니라 distal 링크·모터·포크 등의 자중이 포함된다. stage-2에는 회전하는
부채꼴·타이어·허브의 자중을 포함한다. 동일 부품 자중을 같은 식에 두 번 넣지 않는다.

제조사 토크는 감속기 출력축 기준이다. **내부 감속기 효율을 다시 나누지 않는다.** §6.2의 계수
2.0에 들어 있는 0.75는 관절 바깥의 전달 손실(`external_loss_factor`)이며 내부 감속기 효율과 다른
값이다. 이름이 겹쳐 혼동하지 않도록 `params.json`의 키를 `drive_efficiency`에서
`external_loss_factor`로 바꿨다. 추가 설계 여유를
쓰면 `design_factor`로 명명하고 요구 토크에 한 번 적용한다. D0 스크리닝 계수는 1.5다.

ROBOTIS stall 토크는 순간 최대치다. 전압·속도에 따른 운전점, 전류, 유지 시간, 열 시험 없이
'stall의 39%이므로 연속 유지 가능'이라고 판정하지 않는다.
[W350 자료](https://emanual.robotis.com/docs/en/dxl/x/xm430-w350/),
[W210 자료](https://emanual.robotis.com/docs/en/dxl/x/xm430-w210/)

### 6.4 정지·보행 자세 검색의 고정 절차

B10에서 수행한다. 기구학 계산은 진행할 수 있지만 I07의 전류/열 한계가 없으면 최종 자세의 운전
판정은 BLOCKED다.

1. D0의 기본 질량은 현재 CAD/BOM 추정 합계로 갱신한다. 3.615kg를 고정하지 않는다.
2. `beta` 후보 `[-25,-40,-50.406,-60,-70,-80]`, 절대 스핀각 `0..355°`를 5° 간격으로 평가한다.
   첫 검색에서는 모든 다리 동일 beta·동일 alpha, yaw=0으로 제한한다.
3. 각 alpha에서 h와 접촉 후보를 구하고 H를 만족하는 q1을 해석적으로 구한다. asin 정의역 밖,
   사용 범위 밖, 음수 반력, 안정마진 또는 간섭 위반 후보는 제외한다.
4. 지지 패턴을 **4점 / 3점(다리별 4가지) / 트롯 대각 2점(2가지)** 전부 검사한다. 3점과 2점은
   CoM 이동 요구량을 함께 출력한다.
5. 하드웨어 운전 한계가 있으면 `max(abs(tau_required_j)/tau_allowed_j)`를 최소화한다. 같은 값은
   질량, H 오름차순, alpha 오름차순으로 선택한다. 허용 토크가 없으면 요구 토크 벡터와 기구학
   결과만 출력하고 winner를 null로 둔다.
6. 선택 후보 주변 beta ±5°를 0.5°, alpha ±5°를 0.5°로 재계산한다. 후보가 없으면 b/L/트랙을
   임의 변경하지 않고 G04=FAIL과 위반 조건을 출력한다.

### 6.5 조향·선회와 계단

**직진 굴림에는 조향이 필요 없다.** 진행 방향은 다리가 뻗는 방향(±x)이고 네 부채꼴이 모두 같은
방향으로 구른다. yaw는 ① 보행 시 횡방향 발 배치 ② 선회 ③ 게걸음에 쓴다.

**선회는 좌우 바퀴 속도차를 우선한다.** 조향 선회는 실제 접촉력·미끄럼·토크를 검증한 경로만
허용 목록에 추가한다. 부채꼴 폭이 20 mm뿐이라 스키드 시 횡방향 끌림 저항이 작다는 것은 설계
근거이며 측정값이 아니다. I09에 마찰과 선회 반경 요구를 넣는다.

조향은 우선 스윙에서 수행한다. `N<=0.15Wi`는 자동 운전의 확정 센서 임계값이 아니다.
지지 중 조향 토크는 트레일 182.5 mm, μ=1, N=11.82 N에서 **2.16 N·m**이며 MX-28AT stall
2.5 N·m에 근접한다. 스윙 중(N ≤ 0.15W)에는 0.32 N·m다.

계단 검사는 다음 순서를 고정한다: 평지 정지 → 자세를 개 모드로 전환 → **남은 세 다리 조향각 재배치로
지지 삼각형 확대** → 단일 다리 들기 → 계단 상면에 접촉 → 지지 전환 → 몸체 이동 → 후속 다리 이동 → 하강.

**CoM은 굴림으로 옮길 수 없다.** 미끄럼 없이 구르면 접지점도 몸체와 같은 거리만큼 함께 이동하므로
지지 다각형 대비 CoM 위치는 변하지 않는다. 또 네 발을 딛은 채로 몸체를 수평 이동시키는 것도
불가능하다(다리 길이가 모두 같아야 몸이 수평이므로). 따라서 마진은 **지지 다리의 조향각 재배치**로
만든다(§7.3, 최대 111.0 mm). 몸체를 기울여 만드는 방법도 있으나 80 mm에 롤 15.7°가 필요해 비효율적이다.

관절 끝점 높이 차이 346mm만으로 200mm 계단 통과를 판정하지 않는다. 절차의 성립은 G04에서 검증한다.
## 7. 배치·조향 간섭·안정성

### 7.1 몸체 좌표에서의 중심 이동

조향축은 `(side_x*50, side_y*160, 20.5)`mm다. stage-1 축 높이는 0이며 yaw=0에서 `x=side_x*108`이다.
6족의 중앙 다리 요크 연장 25mm(`mid_yoke_extension_mm`)는 중앙 다리가 없어졌으므로 **삭제**한다.

```text
u_i  = Rz(yaw_i)*(side_x_i,0,0)
v_i  = Rz(yaw_i)*(0,side_x_i,0)
p1_i = (side_x_i*50, side_y_i*160, 0) + 58*u_i
p2_i = p1_i + L_link*(cos(beta_i)*u_i + sin(beta_i)*z_unit)
발_i = p2_i - (0,0,R_tread)        # 원호 접촉일 때만
```

yaw를 주면 발이 조향축 둘레로 반경 `58+arm`의 원을 그린다. 기준 자세에서 이 반경은 **182.478 mm**다.
`e(psi)=R*abs(sin psi)+(b/2)*cos psi` 같은 고정 중심 근사식으로 다리 사이 간섭을 판정하지 않는다.

rev.3의 `psi_max` 파라미터는 삭제 상태를 유지한다. 대신 아래 두 가지를 쓴다.

- **같은 쪽(좌현끼리 또는 우현끼리) 앞뒤 다리 대칭 벌림 한계 = ±64°.** 이 이상 벌리면 앞뒤 부채꼴
  중심거리가 `2*R_tread + 10 = 255 mm` 아래로 떨어진다. `params.json`의 `yaw_search_deg`는
  여유를 두고 **±60°** 로 둔다.
- 그 밖의 조합은 **검증한 경로 목록**으로만 허용한다.

### 7.2 간섭 검사의 실행 범위

B09는 다음을 모두 수행한다. 접촉할 의도가 있는 부품 쌍은 이름·자세·허용 접촉 방식까지 명시한
`allowed_contacts.json`에만 제외한다. 처음에는 지면–타이어와 고정 조립 접합면만 허용한다.

1. 기준 자세: 4개 다리, 몸체, 탑재물, 모터 포락, 포크 전체.
2. 단일 다리 검사: 다른 다리는 기준 자세에 고정하고 yaw `[-60,60]°` 5° 간격, q1 `[-110,115]°`
   5° 간격, q2 `0..355°` 5° 간격. 이 범위는 D0 탐색 범위이며 실제 하드스톱이 아니다.
3. 모든 다리 쌍(6쌍)의 기준 높이 검사: 두 yaw를 각각 `[-60,60]°` 5° 격자로 독립 변화. 같은 쪽
   앞뒤 쌍의 ±60° 반례를 반드시 포함한다.
4. **앞뒤 여유 검사**: `beta`를 `[-80,-25]°`로 훑으며 앞뒤 부채꼴 포락(반경 `R_tread`의 원기둥)
   사이 거리를 확인한다. D0에서 최솟값은 `beta=-80°`의 **38.83 mm**다. `beta=-85°`면 5.0 mm로
   떨어지므로 `beta` 하한을 **−80°** 로 고정한다.
5. q2는 회전 전체를 감싸는 보수적 포락으로 먼저 검사한다. 포락이 겹친 쌍만 실제 부채꼴 형상과 q2
   조합으로 상세 검사한다. 포락 교차를 실제 메시 충돌로 보고하지 않는다.
6. 실제 보행·조향 궤적은 시작부터 끝까지 **12개 관절**을 함께 검사한다. 각도 최대 증분 1°로
   시작하고, 부품 표면의 최대 이동이 최소 여유의 절반보다 작도록 분할한다. 거리 하한을 보장할 수
   없으면 연속 충돌 검사 또는 추가 분할로 확인한다. 해결되지 않은 구간은 PASS가 아니다.
7. 출력: 부품 쌍, 최소거리, 관절각 12개, 경로 시각, 교차 형상, 화면 캡처. 다리의 비접촉 이동 부품
   간 후보 최소 여유는 10mm다. 포크 내부의 의도된 2mm 여유는 별도 쌍 규칙을 적용한다.

**좌우 여유는 문제가 되지 않는다.** yaw=0에서 좌우 부채꼴 안쪽면 사이는 `T - b = 300 mm`다.

단일 다리 격자 검사는 전체 12차원 공간의 무간섭 증명이 아니다. 격자에 충돌이 있으면 그 자세를
기록하고, 실제 경로가 사용하지 않음을 검증한 경우에만 해당 경로를 허용할 수 있다.

### 7.3 무게중심과 지지 패턴

접점은 §7.1의 변환과 §2의 실제 프로파일에서 계산한다. CoM은 부품별 질량과 자세로 계산하고,
페이로드·배터리 위치 오차 범위도 포함한다.

평지 정적 안정마진은 접점의 볼록 다각형 경계까지 CoM 수평 투영의 **부호 있는 최소거리**다.
내부는 양수, 외부는 음수다.

**4점 지지 (굴림·정지).** 접점 `(±232.478, ±160)`.

| 항목 | 이전 후보값 (CoM z=+12 가정) | **D0 실측 (2026-09-09 검수)** |
|---|---:|---:|
| CoM (몸체 좌표) | (0, 0, +12) | **(0.674, 8.923, −65.076)** |
| 지면 위 CoM 높이 | 285 mm | **207.92 mm** |
| 4점 정적 마진 | 160.0 mm | **151.08 mm** |
| 전도각 롤 | 29.31° | **36.00°** (나쁜 쪽) / 39.09° (반대쪽) |
| 전도각 피치 | 39.20° | **48.11°** (나쁜 쪽) / 48.27° |

**실측 CoM이 가정보다 77 mm 낮아 전도 여유가 오히려 커졌다.** 다리가 아래로 뻗어 질량을 끌어내리기
때문이다. 이 값은 현재 CAD 소계(3.115 kg) 기준이며 SPDB·포크·혼·베어링·체결·배선이 빠져 있다.
빠진 것 중 포크·혼·베어링은 다리(낮은 곳)에, SPDB는 데크(높은 곳)에 있으므로 최종값은 이 사이에

**전도각 두 가지를 구분한다.** §16.2의 기준 계산은 CoM 수평 위치를 원점으로 두므로
롤 **37.58°** / 피치 **48.19°** 를 출력한다. 위 표의 36.00° / 48.11° 는 실측 수평 오프셋
`(0.674, 8.923)` 까지 반영해 **불리한 쪽**을 적은 값이다. 두 값이 다른 것은 오류가 아니라
가정이 다른 것이며, 판정에는 불리한 쪽을 쓴다.

**3점 지지 (크롤).** 네 발이 직사각형이면 한 다리를 들었을 때 남은 삼각형의 빗변이 CoM을 정확히
지나므로 마진은 **0.000 mm**다. 네 다리 어느 것을 들어도 같다. 이것은 4족 직사각형 배치의 기하
성질이며 설계 결함이 아니다. 해결책은 다음과 같다.

| 방법 | 얻는 마진 | 비용 | 판정 |
|---|---:|---|---|
| 아무것도 안 함 | 0.0 mm | — | 불가 |
| 몸체 롤/피치로 CoM 이동 | 80 mm에 **롤 15.68°** | 자세 크게 흐트러짐 | 비효율 |
| **지지 다리 3개 yaw 재배치** | **104.4 mm** (실측 CoM) / 111.0 mm (CoM 원점) | 스텝마다 조향 동작 추가 | **채택** |
| 트롯(동적 2점) | 정적 마진 개념 없음 | 균형 제어 필요 | 속도용 별도 모드 |
| 굴림으로 CoM 이동 | **0 mm (효과 없음)** | — | 사용 금지 |

**굴림은 CoM을 옮기지 못한다.** 미끄럼 없이 구르면 접지점이 몸체와 같은 거리만큼 함께 이동하므로
지지 다각형 대비 CoM 위치가 변하지 않는다. 이 사실을 보행 계획에 반드시 반영한다.

yaw 재배치 해는 `yaw_search_deg = ±60`, 다리 쌍 최소거리 255 mm 제약에서 5° 격자로 구했다.

| 드는 다리 | 지지 다리와 yaw | 마진 |
|---|---|---:|
| FL | FR +45° / RR +15° / RL −60° | 104.44 mm |
| FR | FL −45° / RR +60° / RL −60° | 116.50 mm |
| RL | FL +60° / FR −60° / RR −45° | 105.43 mm |
| RR | FL +40° / FR −60° / RL +45° | 117.50 mm |

위 표는 **D0 실측 CoM (0.674, 8.923)** 로 다시 푼 결과다. CoM을 원점으로 두면 네 경우 모두
110.97 mm로 같지만 실제 CoM은 약간 치우쳐 있어 다리마다 값이 달라진다. 최악은 FL을 들 때
**104.44 mm**이며 목표 80 mm를 넘는다. yaw 고정이면 −7.73 ~ +7.73 mm로 사실상 0이다.

yaw ±45°로 제한해도 96.2 mm, ±30°로 제한해도 72.3 mm가 나온다. 목표 80 mm는 **±45° 이내에서
달성**된다. 이 값들은 CoM=(0,0), 기준 자세, 평지 기준이다. 실제 CoM 범위와 자세에서 다시 계산하고,
실패하면 배치를 조정한 새 후보로 다시 검사한다. 경사·계단·가속 중 동적 전도는 평지 정적 마진과
별도 결과로 저장한다.

### 7.4 굴림 중 부채꼴 위상 배치

네 부채꼴의 스핀 위상을 어떻게 어긋나게 두는지가 굴림 승차감을 정한다. 강체는 항상 3점 이상으로
지면에 놓이므로 **위상이 정하는 것은 접지 개수가 아니라 몸의 흔들림 크기**다.

계산 방법: 각 발 위치에서 지지함수 `h(q+offset_i)`를 구하고, `plane(x,y) >= h_i`를 만족하면서
원점 높이가 최소가 되는 평면을 푼다(4개 중 3개 조합을 모두 풀어 실현 가능한 최저해 선택).

| 위상 배치 (FL/FR/RL/RR) | 상하동요 | 피치 | 롤 | 접지 수 |
|---|---:|---:|---:|---:|
| 0 / 0 / 0 / 0 (전부 동상) | 33.25 mm | 0° | 0° | 4 |
| 0 / 0 / 180 / 180 (앞짝·뒤짝) | 16.62 mm | 4.09° | 0° | 4 |
| 0 / 180 / 0 / 180 (좌짝·우짝) | 16.62 mm | 0° | 5.93° | 4 |
| **0 / 180 / 180 / 0 (대각짝)** | **0.00 mm** | 4.09° | 5.93° | **3~4** |
| 0 / 90 / 180 / 270 | 3.82 mm | 4.09° | 5.93° | 3~4 |

**대각짝이 0이 되는 조건은 `접지호 >= 180°` 하나뿐이다.** 접지호가 180°보다 좁으면 비접지 구간이
180°보다 넓어져 대각 두 발이 동시에 그 구간에 들어갈 수 있다. 접지호 195°는 이 조건을 만족한다.
개구각을 더 키우려면 로브 각을 줄여 접지호 180°를 지켜야 한다.

**D0 기본은 대각짝 180°다.** 이유: 개구부(45°)가 180° 떨어진 두 발에서 동시에 바닥을 향할 수 없어
대각 두 발 중 하나는 항상 `h = R_tread`다. 직사각형 배치에서는 원점 높이가 대각 두 발 높이의
평균이므로 결과가 정확히 `R_tread`로 일정하다. 즉 **몸이 위아래로 전혀 움직이지 않는다.**
라이다 스캔 평면과 스테레오 광축이 상하로 흔들리지 않는 것이 가장 큰 이점이다.

기울기가 부담되면 앞짝·뒤짝(피치만 2.29°) 또는 좌짝·우짝(롤만 3.32°)으로 바꾼다. 둘 다 4점 접지를
유지하는 대신 상하동요 9.28 mm를 받는다. 어느 배치를 쓰든 **위상 오차가 누적되면 성질이 무너지므로**
스핀 위상 동기 오차 허용치를 I07에서 정하고 제어기에서 유지한다.

이 표는 강체·평지·미끄럼 없음 가정의 기하 계산이다. 서스펜션 없음, 타이어 변형 무시, 동적 효과
무시다. 실제 승차 특성은 I07/I09의 주행 시험으로 확인한다.

### 8.2 전원 구조와 반드시 채울 정격표

4S 공칭 14.8V/만충 16.8V는 모터의 입력 상한 14.8V를 넘는다. **12V 강압을 사용한다.** 배터리 실제 방전 하한은 셀 제조사 조건과 컨버터 dropout으로 결정하며 13.2V를 확정 컷오프로 쓰지 않는다. [MX-28 사양](https://emanual.robotis.com/docs/en/dxl/mx/mx-28/)

```text
4S 배터리 → 입력 퓨즈/역극성 보호/주 스위치
          ├→ 모터 전원 차단 경로 → 12V 강압 → 보호된 모터 분기
          └→ 5V 강압 → Jetson, LiDAR 별도 전원 경로
Jetson USB → U2D2 → TTL 통신선
센서/통신 기준 접지는 회로의 지정된 공통 접지에 연결
```

이 그림은 회로 토폴로지다. e-stop의 실제 접점·전류 정격·우회 전원 유무와 차단 후 기체 지지 상태는 I06에서 검증해야 한다.

12V stall 전류의 참고 합은 한 다리 1.4+2.3+2.3=6A, **12개 합 24A**다. 정상 전류나 필수 컨버터 정격을 뜻하지 않는다. 기존 ‘12V 10A/5V 5A/30A 입력 퓨즈/5A 분기 폴리퓨즈’는 확정 부품 선정에서 내려 **비교 후보**로 둔다.

I06 정격표는 각 전원 경로마다 다음 열을 포함한다:

`source, load_ids, normal_A, rms_A, peak_A, peak_duration_ms, current_limit_A, voltage_min_max, wire_AWG_length, connector_SKU_rating, fuse_SKU_curve, converter_SKU_derating, evidence`.

1. 전류 제한·기동 순서·모터 duty를 I07의 동작과 연결해 레일 부하를 계산한다.
2. 커넥터·전선·동박·비아·퓨즈의 시간별 허용 전류를 함께 검사한다. JST EH는 AWG22에서 3A 정격이므로 5A 폴리퓨즈가 자동으로 보호한다고 가정하지 않는다. 10A용 ‘2.54mm 4P’ 소켓은 삭제하고 정확한 SKU와 핀별 정격을 정한다. [JST EH](https://www.jst-mfg.com/product/index.php?series=58)
3. 전류 제한에 의존하면 실제 제한 동작과 과도 펄스를 시험한다. 다이나믹셀 연결 규격 때문에 한 경로의 허용 전류를 넘는 경우 모터별 전원 분기 또는 동작 제한을 설계하고 회로로 입증한다. 통신과 전원 분기를 혼동하지 않는다.
4. 정지→동시 기동, 방향 반전, 감속/하강, 잠금, 저전압에서 레일 전압을 측정한다. 2000µF는 추가 5A를 1V 강하까지 약 0.4ms만 담당한다.
5. 모터가 되돌리는 에너지를 컨버터가 수용하는지 확인한다. 역전류 불가 벅이면 별도 에너지 흡수/클램프 경로가 필요하다. 부품 미선정 상태에서 TVS 하나로 해결됐다고 표시하지 않는다. [TI 역전력 설명](https://www.ti.com/document-viewer/lit/html/SSZT878/GUID-72E4FF4E-0508-4018-A599-5B6605492BD5)
6. Jetson 입력에 USB/CSI 부하가 포함되는지 구분한다. 문서상 4A와 LiDAR 기동 1A만 합쳐도 5V 5A에는 여유가 없다.
7. INA226은 측정기다. 셀별 저전압 판단·실제 차단·재기동 조건을 별도 구현한다. I06이 없으면 PCB 발주/전원 투입 준비 판정은 BLOCKED다.

### 8.3 센서 운용과 시야

IMX219-83은 하드웨어 프레임 동기화를 지원하지 않으며 IMU와 영상도 동기화되지 않는다. 카메라 두 개의 CSI와 IMU용 I²C를 모두 배선하고 타임스탬프·노출·움직임의 영향을 측정한다. [Waveshare 공식 문서](https://www.waveshare.com/wiki/IMX219-83_Stereo_Camera)

깊이 오차식 `sigma_z=z^2*sigma_d/(fx*baseline)`에는 해상도, 실제 보정 fx, baseline, 시차 오차 sigma_d를 함께 기록한다. 기존 1m에서 3.6mm는 fx≈2317px, baseline≈60.1mm, sigma_d≈0.5px라는 정적 가정이며 이동 중 정확도를 보장하지 않는다.

D0는 **광학 중심**을 (70,0,70)mm, 광축을 전방(+x)에서 30° 하향으로 정의한다. H255 지면 -273mm에서 높이는 343mm, 수직 FOV50° 가정의 지면 교점은 광학 중심 바로 아래에서 **240.2–3920.6mm 전방**이다. 이 좌표는 보드 중심이 아니다. D1에서 광축–홀 변환으로 브래킷을 만든다. 좌표와 방향 규칙은 §9.2에 있다.

LiDAR D0 베이스는 (0,-20,70)mm, 스캔 평면 높이는 베이스+26.3=96.3mm로 둔다. 실제 도면과 일치하면 이 값을 유지한다. 본체·배선·마스트 차폐를 광선 검사하고, **4족은 앞다리가 근거리 전방을 크게 가리므로** 다리의 일시 차폐는 각도·지속시간·최대 연속 가림을 보고한다. 단순 각도 마스킹이 시야를 복원한다고 주장하지 않는다.

T-mini Plus의 5V/typical 340mA/기동 최대 1A는 제조사 자료 참고값이다. [데이터시트 URL](https://www.ydlidar.com/Public/upload/files/2024-05-24/YDLIDAR%20T-mini%20Plus%20Data%20Sheet_V1.1%20%28240131%29.pdf)은 이전 검토에서 검색에 남은 원문 내용은 확인했으나 직접 다운로드가 404였다. 다음 에이전트는 현행 제조사 자료 또는 보유품 도면을 I05에 저장하고 핀 번호·도면을 확정해야 한다.

### 8.4 질량 예산의 처리

**총질량 3.615 kg은 확정값이 아니라 하중 입력용 후보값(CANDIDATE)이다.** 산출 경로는 다음 한 줄이다.

```text
3.615 kg = 4.945 kg (rev.3 D0 무공 형상 6족 추정) - 2 x 0.665 kg (다리 모듈)
다리 모듈 0.665 kg = 모터 0.241 kg (77+82+82 g) + 다리 구조 0.424 kg
```

이 값은 **몸체 축소분을 반영하지 않았다.** 몸체 y 길이가 425→350 mm로 줄었으므로 실제 값은 더
가벼울 가능성이 높다. 즉 보수적 상한 쪽이다. rev.2 BOM의 23개 행 합계 4569.2g은 산술적으로
맞으며 올바른 분류는 모터 1446g, 구조 2285.2g, 전장·센서·배터리 568g, 배선·체결류 270g이다.
기존 '구조 2777 / 전장 346'과 증가분 전부가 전장이라는 설명은 폐기 상태를 유지한다.

D0는 무공 링크·무포켓 웹·미가공 허브를 사용하므로 rev.2 질량과 달라진다. **139.8g 판, 63.2g 링크,
4.569kg 총질량에 CAD 밀도를 맞추지 않는다.** 질량 예산은 생성 결과에서 다시 계산한다.

|---|---|---:|---:|---:|

| XM430-W350-T | stage-1 (q1) | 4 | 82 | 328 |
| XM430-W210-T | 부채꼴 스핀 (q2) | 4 | 82 | 328 |

`parts_manifest.json`의 부품마다 `part_id, instance_id, revision, role, mass_source, mass_kg,
com_local_m, inertia_com_local_kgm2, geometry_hash, source_file`을 기록한다. mass_source는
`CAD_BULK`, `ENVELOPE_EFFECTIVE`, `DATASHEET`, `MEASURED` 중 하나다. 값이 없는 항목은 null이고
누락 개수와 부분합을 함께 보고한다.

- PLA: 실제 생성한 재료 체적×예비 벌크 밀도. D1에서는 출력 질량과 대조한다.

  않는다. 경량화 효과는 변경 전후 동일 하중으로 재검증한다.
- B05가 총질량을 갱신하면 §3의 `N_ref`, §6의 설계토크, §7의 전도각을 **모두 다시 계산**한다.
  3.615 kg에 맞추어 다른 표를 고정하지 않는다.

## 9. 몸체·배치·배선·PCB

### 9.1 D0 몸체 형상

좌표는 mm다. 하부 기준 하면 z=-18은 모든 높이 계산의 원천이다. 몸체는 **앞뒤 130 mm(x±65),
좌우 350 mm(y±175)** 다. 좌우가 긴 이유는 조향축이 `y=±160`에 있어야 트랙 320 mm가 나오기
때문이다. 앞뒤 방향 크기는 다리가 만들므로(축거 465 mm) 몸체 자체는 짧아도 된다.

1. 외곽은 x±65, y±175의 사각 둘레다. 바깥 박스빔은 평면 폭 12, 높이 10, 벽 2.4mm이며
   z=-18..-8에 둔다. 코너는 미터 접합으로 닫는다.
2. **횡 리브**는 y=-160 / 0 / +160, 두께 2.4, x=-53..53, z=-18..-8이다. y=±160 리브가 조향

### 9.2 D0 탑재물의 좌표와 방향

아래 XYZ는 스테레오를 제외하고 **몸체 좌표 축 방향의 포락 크기**다. 스테레오의 크기는
폭/보드 높이/광축 방향 두께이며 바로 아래 변환을 적용한다. 원래 부품의 L/W 명칭을 다시 해석하지
않는다. `center`는 XYZ 중심, `base`는 XY 중심과 최저 z, `optical`은 광학 중심이다.

**스테레오.** optical을 원점으로 보드 폭을 **y 방향**, 보드 높이를 광축에 수직인 위쪽, 두께를 광축
방향으로 배치한 보수적 중심 블록이다. 광축은 `(cos30°,0,-sin30°)`, 보드 위쪽은 `(sin30°,0,cos30°)`다.
실제 광학 중심의 보드 내 오프셋은 I05에서 보정한다. 이 블록은 마운팅 홀을 정의하지 않는다.

광학 중심 z=70, 지면 z=-273이므로 **높이 343 mm**다. 수직 FOV 50°, 하향 30° 가정에서 지면 교점은
광학 중심 바로 아래에서 **240.2–3920.6 mm 전방**이다(rev.3의 313 mm / 219.2–3577.6 mm를 대체).
지면 교점 거리는 높이에 비례하므로 실제 높이가 확정되면 같은 비율로 다시 계산한다.

**전방 시야 가림.** 개 자세(β=−70°)에서 앞 부채꼴 중심은 x=174.8, 반경 122.5이므로 지면에서
x=52..297 구간을 가릴 수 있다. 근거리 시야가 앞다리에 가리는 것은 4족에서 피할 수 없으므로,
G09에서 **자세·스핀각별 가림 구간과 최대 연속 가림 시간**을 기록한다. 단순 각도 마스킹으로
시야가 복원된다고 주장하지 않는다.

**라이다.** 베이스 z=70, 스캔 평면은 베이스+26.3=96.3 mm(지면 위 369.3 mm)다. rev.3의 64/90.3보다
6 mm 올렸다. 이유는 스테레오 상단(약 z=85.4)이 전방 스캔을 막지 않게 하기 위해서다. 실제 도면과
스테레오 브래킷이 정해지면 이 6 mm를 재확인한다.

포락 교차는 실제 트러스 부재의 교차와 구분해 보고한다. 마스트/Jetson 포락이 겹치면 숨기지 않고
D1 실부재로 해소할 대상이라고 남긴다.

## 11. 좌표계·관절·번호 규약

### 11.1 몸체와 다리의 기준

몸체 원점은 좌우/전후 중심과 stage-1 축 높이 z=0의 교점이다. **+x 전방, +y 좌현, +z 상방**이다.
세계 좌표와 몸체 좌표가 일치하는 기준 자세에서만 아래 수치를 그대로 읽는다. 몸체가 기울거나
이동하면 전체 몸체 변환을 앞에 곱한다.

**rev.3(+x 우현, +y 전방)에서 축 이름이 바뀌었다.** 이유는 하나다. 이 기구의 **진행 방향은 다리가
뻗는 방향**이고, 4족에서 다리는 앞뒤로 뻗는다. 그러므로 다리가 뻗는 축이 전방(+x)이어야
"앞으로 굴러간다"는 말과 좌표가 일치한다. rev.3에서 "전방 = 몸통 장축(+y)"으로 잡았다가
"조향 없이는 전방 굴림 불가"라는 잘못된 결론이 나왔다. 그 원인을 좌표 정의 단계에서 제거한다.

| 다리 | 위치 | side_x | side_y | 조향축 (x,y,z) mm | 논리 모터 번호: yaw / q1 / q2 |
|---|---|---:|---:|---|---|
| FL | 전방 좌 | +1 | +1 | (+50, +160, 20.5) | M01 / M05 / M09 |
| FR | 전방 우 | +1 | −1 | (+50, −160, 20.5) | M02 / M06 / M10 |
| RL | 후방 좌 | −1 | +1 | (−50, +160, 20.5) | M03 / M07 / M11 |
| RR | 후방 우 | −1 | −1 | (−50, −160, 20.5) | M04 / M08 / M12 |

`side_x`는 다리가 뻗는 방향(전/후)이고 `side_y`는 좌우 위치다. **`u_i`를 만드는 것은 `side_x`뿐이며
`side_y`는 조향축의 y 좌표만 정한다.** 둘을 섞지 않는다.

M번호는 **CAD 논리 식별자**이며 실제 다이나믹셀 ID라고 가정하지 않는다. I01에서 대응을 확인한다.
다리 프레임의 열벡터는 `F_i=[u_i,v_i,w]`, `w=(0,0,1)`이며 `u_i=Rz(yaw_i)*(side_x,0,0)`,
`v_i=Rz(yaw_i)*(0,side_x,0)`다. 두 방향을 함께 뒤집어 후방 다리도 오른손 좌표계를 유지한다.
음의 scale로 솔리드/관성을 미러하지 않는다.

### 11.2 관절과 순기구학의 정확한 정의

| 관절 | 세계/몸체 방향 | 양의 동작 | 영점 |
|---|---|---|---|
| yaw | +z | 위에서 볼 때 반시계 | 링크가 해당 다리의 전/후 바깥으로 향함 |
| q1 | `-v_i` | 링크 기준 +u가 +w 쪽으로 올라감 | 크랭크 첫 구간이 +u |
| q2 | `-v_i` | 부채꼴의 +u 기준점이 +w 쪽으로 회전 | q1=0일 때 §2 프로파일과 일치 |

```text
p_steer = (side_x*steer_axis_x, side_y*track_half_y, steer_axis_z)
p1 = (side_x*steer_axis_x, side_y*track_half_y, stage1_axis_z)
     + (stage1_axis_x-steer_axis_x)*u_i
A = link_a + link_b*cos(gamma)
B = link_b*sin(gamma)
p2 = p1 + (A*cos(q1)-B*sin(q1))*u_i
        + (A*sin(q1)+B*cos(q1))*w
alpha_abs = q1+q2
p_sector(chi,v) = p2 + rho(chi)*cos(chi+alpha_abs)*u_i
                     + v*v_i
                     + rho(chi)*sin(chi+alpha_abs)*w
```

q1의 양의 회전은 앞뒤 다리 모두 발을 위로 올리지만 세계축은 전방 다리 −y, 후방 다리 +y로 다르다.
q2 역시 로컬 −v축이며 부채꼴 평면의 굴림 방향은 ±u다.

**굴림 방향.** `v_axle=-omega x r_contact`로 검사한다. yaw=0에서 `u`는 전방 다리가 +x, 후방 다리가
−x다. **전진(+x)하려면 전방 다리는 q2가 음의 속도, 후방 다리는 q2가 양의 속도**여야 한다.
좌우(y)에 따른 부호 차이는 없다. 네 부채꼴의 장착 헤딩은 모두 같고 조향은 필요 없다.
`joints.json`의 `roll_direction_sign`에 다리별로 `-side_x`를 기록하고 제어기에서 그대로 쓴다.

**스핀 위상 오프셋.** D0 기본은 §7.4의 대각짝 배치다. `spin_phase_offset_deg`는
FL=0, FR=180, RL=180, RR=0이다. 이 값은 파라미터가 아니라 **보행/주행 명령의 초기 조건**이므로
`params.json`이 아닌 `gaits/*.json`에 둔다.

Fusion/MuJoCo의 계층 변환은 다음 순서다: 몸체 → 조향축의 위치와 후방 다리 기본 회전 → yaw(+z) →
stage-1까지의 고정 변환 → q1(로컬 −y) → 크랭크 끝점 고정 변환 `(A,0,B)` → q2(로컬 −y) → 부채꼴.
Euler 부호를 임의로 보정하지 않고 위 순기구학과 좌표를 대조한다.

부품 부착 기준은 다음으로 고정한다. 각 부품의 실제 장착면 오프셋은 I02/I05에 저장하며 회전 계층과
혼동하지 않는다.

| 부품 | 움직임을 따르는 프레임 |
|---|---|
| 하부 프레임·데크·탑재물·yaw 모터 하우징 | 몸체 고정 |
| 요크 #1/#2·stage-1 모터 하우징 | yaw 이후, q1 이전 |
| 크랭크·포크·stage-2 모터 하우징 | yaw와 q1 이후, q2 이전 |
| 부채꼴·타이어·회전 허브 | yaw/q1/q2 이후 |
| 샤프트·베어링 내/외륜·체결류 | I02 조립 단면의 고정/회전 구분; 미확인 시 D1 BLOCKED |

yaw 모터 하우징의 참고 중심은 `(side_x*36.7, side_y*160, 3.3)mm`다. 회전축
`(side_x*50, side_y*160, 20.5)mm`와 다른 점임을 유지하고 실제 CAD에서 확인한다. 모터 형상이
없으면 하우징 중심과 축의 두 마커만 표시한다.

## 12. 물성·관성·MuJoCo 이관

### 12.1 부품 집계

`parts_manifest`가 집계의 원천이다. `_STUDY_` 포락, 숨긴 중복 부품, 원본 참조 조립체는 기본 제외하며, 질량을 가진 payload 대체 블록은 명시적으로 한 번 포함한다. Fusion의 표시 숨김과 질량 제외를 동일하게 취급하지 않는다.

| 물성 종류 | D0 | D1 |
|---|---|---|
| 구조 PLA | §10 예비 벌크 밀도·탄성값 | 실제 출력 방향별 밀도·강도·E/G |
| TPU 외형 | 실효밀도 질량, 강성 미정 | 실제 셀/재료/접촉 시험 |
| 모터·전자부품 | 도면 질량 또는 추정 질량과 상태 | 보유품 리비전·실측 질량 |
| 관성 | 형상 기반 예비값 | 실제 분포/조립 범위와 검증 |

B03는 `MARC_v4_PLA_D0`, `MARC_v4_TPU_envelope_D0` 사용자 재료를 만들고 §10의 밀도를 각 구조/타이어 바디에 명시적으로 배정한다. 같은 이름의 다른 값이 이미 있으면 기존 재료를 수정하지 않고 실행 ID를 붙여 복제한다. `_STUDY_`와 모터 마커는 물성 집계에서 제외한다. 미배정 기본 강철 바디가 부품 목록에 남으면 G05 FAIL이다. D1 재료는 별도 이름과 I04 시험 리비전으로 생성한다.

질량만 일치시키려고 직육면체 밀도를 조정한 모터 모델은 실제 CoM/관성과 동일하지 않다. 제조사 CAD·질량 자료가 없는 축은 관성 검증 상태를 별도로 둔다.

### 12.2 Fusion 관성 변환

`getXYZMomentsOfInertia()`는 세계 원점 기준, kg·cm² 단위다. 결과 성공 플래그와 성분 순서를 확인하고 **×1e-4**로 kg·m²로 바꾼다. [Autodesk API](https://help.autodesk.com/cloudhelp/ENU/Fusion-360-API/files/PhysicalProperties_getXYZMomentsOfInertia.htm)

1. Python 반환 순서는 `(success,xx,yy,zz,xy,yz,xz)`다. API 설명만으로 교차 성분 부호를 단정하지 않고 아래 B05 시험으로 adapter를 결정한다. `xy`가 교차적분 `integral(x*y dm)`이면 텐서의 비대각 성분은 그 음수다.
2. 별도 스터디에서 균일 직육면체 XYZ=20×30×40mm, 밀도 1.18g/cm³를 만든다. 중심 원점/무회전 경우와 중심 c=(100,200,300)mm, 회전 `Rz(30deg)*Ry(20deg)`인 경우를 검사한다. 분석해는 m=0.02832kg, `I_COM_local=m/12*diag(0.03^2+0.04^2,0.02^2+0.04^2,0.02^2+0.03^2)`, `I_origin=R*I_COM_local*R^T+m*((c·c)*Id-c*c^T)`이며 c는 m로 넣는다. 반환 비대각을 그대로/음수로 넣은 두 adapter 중 전 성분이 `max(1e-10kg·m²,1e-5*max_abs(I_expected))` 이내인 하나만 채택한다. 둘 다 실패하거나 둘 다 통과하면 G05 FAIL이다. 선택 결과와 Fusion 버전을 저장하고 실제 바디와 occurrence의 좌표 변환도 같은 시험으로 검증한다.
3. COM 벡터 c를 m로 변환한 후 `I_COM=I_origin-m*((c·c)*Id-c*c^T)`로 옮긴다.
4. 실제 회전축 위의 점 a와 단위 방향 n에 대해 `d=c-a`, `I_axis=n^T*(I_COM+m*((d·d)*Id-d*d^T))*n`을 계산한다.
5. MuJoCo에는 부품 **COM 기준, 해당 로컬 프레임**의 관성을 넣는다. 위 I_axis를 그대로 body inertia로 넣어 armature와 이중 집계하지 않는다.

물성 API의 질량은 kg, 체적은 cm³, 밀도는 kg/cm³다. 문서의 1.18g/cm³를 해당 API 단위로 비교하면 0.00118kg/cm³이며, 소재 편집 API가 다른 단위를 요구하면 그 스키마대로 변환한다. 텐서의 대칭성·양의 고유값·주관성의 삼각 부등식도 확인한다. [물성 API 단위](https://help.autodesk.com/cloudhelp/ENU/Fusion-360-API/files/PhysicalProperties.htm)

스핀 관성의 부품 범위는 **회전하는 PLA 부채꼴+TPU+회전 허브/스터브/체결류**다. 고정 모터 케이스와 포크는 제외한다. 후보 목표 2.2e-3kg·m²와 비교할 때 이 범위를 함께 표기한다. `Izz`라는 이름으로 축을 생략하지 않는다.

- volume/area/referencePlane API 예외는 개별 대상과 메시지를 기록한다. 실패한 부품을 질량 0으로 넣고 검사를 통과시키지 않는다.
- 현재 도구 스키마가 필요한 API를 제공하지 않으면 이름을 추측해 호출하지 않는다. 로컬 Fusion 스크립트 실행 방식으로 전환한 사유와 방법을 기록한다.

### 14.2 D0 진단 경로의 정확한 정의

경로 배열의 관절 순서는 `[M01..M04, M05..M08, M09..M12]` = `[yaw FL,FR,RL,RR, q1 FL,FR,RL,RR,
q2 FL,FR,RL,RR]`, 단위 rad, 시간 s다. 초기 자세는 §6의 yaw=0, q1 기준값, q2=−q1이다.
보간은 구간마다 `f(t)=3*s^2-2*s^3`, `s=(t-t0)/(t1-t0)`를 사용한다. 초기 관통이 있으면 경로를
실행하지 않고 시작 자세 FAIL을 기록한다.

| 경로 ID | 구간 | 목적 |
|---|---|---|
| P00 | 0..1s 초기 자세 유지 | 좌표/지지점/정적 간섭 |
| P01-Li | 0..2s 선택 다리 q1을 기준+20°로; q2=−q1 유지. 2..4s yaw 0→+60°. 4..8s +60→−60°. 8..10s −60→0°. 10..12s 초기 복귀 | 다리 4개 독립 스윙/조향 진단 |
| P02-pair | 6쌍 전체에 대해 두 다리를 P01처럼 든 뒤, 2..4s yaw 0→(+45,−45)°, 4..8s→(−45,+45)°, 8..10s→(0,0), 10..12s 복귀. **같은 쪽 앞뒤 쌍은 (+60,−60)까지 확장** | 조향 중심 이동 반례, 앞뒤 부채꼴 간섭 |
| **P03-crawl-Li** | 0..2s 지지 3다리를 §7.3 표의 yaw로 이동. 2..4s 선택 다리 들기. 4..6s 내리기. 6..8s yaw 복귀 | **정적 크롤 1스텝의 간섭·마진 동시 검증** |
| **P04-beta** | 0..4s 네 다리 beta −50.406→−70°(개 자세), 4..6s 유지, 6..10s −70→−25°(스파이더), 10..14s 복귀 | 자세 전환 전 구간의 앞뒤 여유·지면 관통 |
| P05-Li | 단일 다리 스터디의 지면 z=0, 축 중심 (0,0,R_tread+10mm). q1은 기준값, yaw=0을 유지하고 q2 0→360° 8s | 1회전 접지 형상·포크 간섭 |
| **P06-phase** | 네 다리 q2를 §7.4 대각짝 오프셋(0/180/180/0)으로 두고 동시에 0→720° 12s | 굴림 위상 배치의 접지·상하동요 확인 |

P01의 +20°가 실제 다리를 충분히 띄우는지 접촉 계산으로 확인한다. 지면을 계속 관통하면 실패로
남기고 임의 높이를 추가하지 않는다. P04에서 `beta=-80°` 부근의 앞뒤 여유 38.83 mm를 실제 형상으로
확인한다. 이 경로들은 **진단용**이며 지지 안정성이 검증된 보행 명령이 아니다. 시뮬레이션/실물
동적 실행은 해당 관문 통과 뒤 별도 수행한다.
### 14.3 결정이 필요한 경우의 처리

| 상황 | 정해진 처리 |
|---|---|
| CAD 형상 생성 실패 | 실패 feature와 입력 저장; 단계 FAIL. 자동 형상 변경 금지 |
| 측정/도면 없음 | I번호·필드·확보 경로를 기록, 종속 관문 BLOCKED |
| 간섭·토크·질량 목표 실패 | 실패 후보 보존, 위반량과 민감도 표 작성; 임의 목표 완화 금지 |
| 기존 파일/문서가 이미 있음 | 소유 manifest와 해시 확인; 자기 이전 산출물만 갱신, 나머지는 새 실행 경로 |
| 단위/좌표 불일치 | 전체 변환을 §11/§12로 추적해 수정; 임의 sign/scale 보정 금지 |
| 입력이 충분한 루틴 구현 선택 | 이 명세의 데이터 계약과 검사를 만족하는 코드로 구현하고 버전 기록 |

새 설계 후보가 필요한 경우 기존 D0를 덮어쓰지 않고 `candidate_id`, 바꾼 파라미터, 변경 이유, 재실행할 관문을 명시한다. 문서에 없는 물리 치수·성능 한계를 확정할 결정은 필요한 근거/선택을 모아 한 번에 정리한다. 이미 실행 가능한 계산을 끝내기 전에 단순 구현 취향을 질문하지 않는다.

### 14.4 구현 진입점과 재실행 규칙

모든 B단계 구현은 `run(ctx)`를 진입점으로 제공한다. ctx에는 `repo_root`, `run_dir`, `stage`, `document_id`, `params_sha256`를 넣는다. `repo_root/run_dir`는 절대 경로, stage는 D0 또는 D1, document_id는 최초 생성 전만 null이다. 설정을 전역의 `active_run` 파일에 공유하지 않는다.

- B00는 로컬 CLI로 `--repo-root`와 `--run-dir`를 받으며 새 실행 디렉터리를 만든다. 나머지 순수 계산 단계 B01/B02/B08/B10/B14는 `--run-dir`에서 ctx를 읽는다. source_manifest의 원문·입력 해시가 달라지면 새 실행 디렉터리를 요구한다.
- Fusion 단계 B03–B07/B09/B13는 B00가 만든 실행 디렉터리의 `cad/dispatch_Bxx.py`로 호출한다. dispatcher는 해당 실행의 ctx를 명시적으로 넣고 버전이 고정된 구현의 `run(ctx)`를 호출한다. `fmcp.py script`에 전달할 파일은 이 dispatcher다. Fusion의 현재 작업 디렉터리나 `__file__`이 저장소를 가리킨다고 가정하지 않는다.
- B03의 최초 document 생성은 새 ID를 반환하고 ctx에 저장한다. 나머지 Fusion 변경은 이 ID를 확인한 뒤 실행한다. 스터디용 관성 시험은 별도 문서에서 수행하며 로봇 문서 ID를 덮어쓰지 않는다.
- B11/B12는 해석/측정 산출물을 읽어 판정하는 도구다. 계산 도구 호출만으로 물리 시험을 자동 실행하거나 결과를 생성하지 않는다. 시험 결과가 없으면 해당 입력을 BLOCKED로 반환한다.
- 각 단계는 `{step_id,status,outputs,checks,blocking_inputs,error}`를 반환한다. Python 예외/API 실패가 있으면 status=FAIL이며 출력 파일이 생겼다는 이유로 성공으로 바꾸지 않는다.
- 산출물은 임시 파일에 쓴 뒤 유효성 확인 후 교체한다. 실패한 실행의 마지막 정상 산출물은 보존하되, 새 입력의 성공 결과처럼 재사용하지 않는다.

§13의 단순 `fmcp.py script` 예시는 전송 형식 설명이다. 실제 후속 실행 명령은 생성된 dispatcher의 절대 경로로 기록한다. 이 진입점 계약은 구현할 명세이며, 현재 실행 가능한 B00–B14 파일이 있다는 뜻이 아니다.

### 15.2 후보 목표와 미확정 요구

질량 **3.90kg**, 4점 정적 마진 80mm, **3점(yaw 재배치 후) 정적 마진 80mm**, SF4, 판 변위 0.53mm,
링크 비틀림 0.10°, 스핀 관성 2.2e-3kg·m²가 rev.4의 설계 목표다. 질량 목표만 4족 전환에 맞춰
4.75kg에서 내렸고 나머지는 rev.2에서 계승한 값 그대로다. 이 문서는 목표를 몰래 완화하지 않는다.
서로 양립하지 않으면 실패를 근거로 새 목표/후보를 제시한다.

당시 형상(접지호 225°)의 `2*pi*R_tread*(225/360) = 481.06 mm`가 문서 26/28/29와 ICRA 투고본에
"회전당 전진거리"로 실려 있었다. 그 형상의 실제 값은 752.81 mm였다. **개구각 75°로 바꾼 현재
형상**의 값은 회전당 **739.54 mm**이며, 접지호 416.92 mm + 로브 굴림 185.65 mm + 팁 피벗 현
136.97 mm(전체의 18.52%)로 나뉜다. **481 mm는 회전당 이동거리가 아니라 접지호의
호 길이였다.** 이 값을 쓴 모든 문서를 §19.3 목록에 따라 정정한다.

| R7 | §6.2와 §6.3의 효율 0.75 모순 | 같은 이름을 다른 뜻으로 사용 | `drive_efficiency` → `external_loss_factor`로 개명하고 두 절에 근거 명시 |

**검수에서 되돌린 것.** 모터를 부모 링크에 강체 조인트로 묶었더니 Fusion이 조립을 다시 풀면서
모터 12개를 모두 대각선 반대 모서리로 옮겼다. 조인트를 지우고 좌표만 다시 지정했다.
모터가 관절을 따라 움직이게 만드는 것은 B06/D1 과제로 남긴다. 운동학적 부모는 메타데이터로만
기록되어 있다.

**바뀌지 않은 것.** 부채꼴·타이어 프로파일, 링크 등가 길이, 기준 자세, 프레임·데크·탑재물 배치,
파라미터 48개의 값(위 두 개 제외), 관문 체계.
